# IMU 잘 쓰기 — 계획 (2026-10-18)

목표: 폰(S24) IMU를 최대한 정확하게 써서 VIO(OpenVINS)를 덜 틀어지게 만든다. 다른 일(ARCore, 루프 클로저, 논문 비교)은 멈춤.
판정 기준: **IMU만으로 1 s / 3 s 동안 쌓이는 위치·각도 오차** (정답 궤적 대비)와 VIO 시작↔끝 오차.

## 0. 이미 확인·해결한 것
- 시계: 카메라 SENSOR_TIMESTAMP 와 SensorEvent.timestamp 가 같은 시계(elapsedRealtimeNanos 기준). 카메라는 노출 중간 시각으로 넣음.
- 비율: 자이로 502 Hz, 가속도 502 Hz (HIGH_SAMPLING_RATE_SENSORS).
- **가속도 몰림**: S24는 가속도를 약 12 ms마다 여러 개씩 한꺼번에 줌. 마지막 2개만 쓰면 84 %가 같은 값 → OpenVINS 수십 m 이탈.
  모든 샘플을 모아 자이로 시각에 보간하게 고침 (phone_stereo/arlat OvRunner.flushImu, 2026-10-18).
- 카메라 → 앱 도착 68~80 ms, OpenVINS 계산 13~20 ms (S24).

## 1. IMU 특성 실측 (폰만 있으면 됨)
| 항목 | 방법 | 결과물 |
|---|---|---|
| 잡음·바이어스 안정성 | 폰을 2~3 시간 가만히 두고 기록 → 앨런 분산 | 자이로/가속도 noise density, random walk → OpenVINS 설정값 |
| 샘플 간격 흔들림·빠짐 | 같은 기록에서 시각 간격 분포, 몰림 크기 | 보간·버퍼 설계 근거 |
| 온도 영향 | 기록 중 배터리/CPU 온도 같이 기록 | 바이어스 대 온도 |
| 가속도 축척·축 어긋남 | 6면 정지 자세(각 면 10 s) | 축척·직교 보정값 |

## 2. 카메라–IMU 맞춤
- 시간차: OpenVINS 온라인 추정(dt_cam_imu) 값을 여러 녹화에서 모아 고정값 확인 (지금 2~29 ms로 흔들림 → 원인 확인).
- 상대 자세(외부 파라미터): 온라인 추정 수렴값을 녹화별로 비교, 흔들리면 보정판으로 한 번 정밀 측정.

## 3. 실시간에서 IMU 쓰는 법
- IMU로 지금 시각까지 앞당긴 위치 출력(500 Hz) — 카메라 지연(약 80 ms)을 체감에서 없앰.
- 정지 감지(ZUPT): 바닥에 있을 때 속도 0으로 묶어 바이어스 추정.
- 진동: 드론에서는 방진 마운트 + 진동 주파수 확인(모터 회전수 대역) 후 필요하면 필터.

## 4. 학습으로 IMU 고치기 (정답 궤적이 생긴 뒤)
- 혼합 방식(AirIMU식): 신경망이 IMU 샘플 보정값 + 불확실성을 내고, 적분은 물리식 그대로. 과거만 보는 창 → 추가 지연 없음.
- 정답 궤적: 바닥 마커 격자(저렴한 모션 캡처).

## 순서
1 → 2 → 3 (정지 감지·앞당기기) → 정답 궤적 준비 → 4.
