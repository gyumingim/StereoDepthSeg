## 결론 먼저
1. **정지 출발 (`--init-still 1`)**: 쓰면 안 됨 (기본 꺼짐 유지). 폰이 가만히 있어도 0.73 s 만에 초기화되지만
   정지 중에는 시차가 없어 영상 갱신이 1.5–3 s 동안 없고, 첫 갱신이 가짜 속도(0.4–1.7 m/s)를 넣는다.
   오프라인 42 셀: **발산 37 / 39** (채점된 셀; 3 셀 점수 없음) (지금 방식 8 / 42). 폰 정지 실측(스트림 재생): 0.74 s 초기화 → 2.8 s 에 **0.5 m 튐**,
   그 뒤 60 s 동안 7 cm 안. 지금 방식은 정지 62 s / 74 s 동안 **한 번도 초기화 안 됨** (live 2회).
   → OpenVINS 는 ZUPT 없이 정지 중 상태를 유지할 수 없다 (정지 출발 = ZUPT 와 묶여 있는 설계, VioManagerHelper
   `wait_for_jerk = updaterZUPT == nullptr`). 드론용 대안: 지금처럼 "정지 → 이륙 순간 jerk 로 초기화" +
   **`init_ready` 신호** (아래 2) 로 "이륙하면 초기화된다" 를 미리 확인.
2. **상태 출력 (`--health 1`, `--health-log FILE`)**: 프레임마다 INIT/OK/DEGRADED/LOST + 추적 점 수, MSCKF/SLAM 사용 점,
   chi2 거부, 위치·속도·자세 표준편차, 마지막 영상 갱신 뒤 시간, 초기화 전 `init_ready`. **포즈 변화 없음**
   (PC 845 프레임 + 오프라인 42/42 셀 + 폰 2327 프레임 해시 동일), 폰 처리 시간 차이 없음 (p50 10.79 → 10.76 ms, 1 회씩).
3. **자동 복구 (`--recover N`, 기본 꺼짐)**: 2 s 영상 끊김 합성 시험에서 OpenVINS 는 **스스로 0.1 s 만에 되살아난다**
   (끊김 뒤 정확도 0.56 cm, 끊기지 않은 같은 구간 0.46 cm). 첫 정책(v1, 영상 돌아오자마자 상태 주입)은 오히려 나빴음
   (10 cm 넘는 셀 5 → 14) → v2 (영상이 돌아온 뒤에도 N 프레임 동안 갱신이 없을 때만 주입, 전체 리셋은 `--recover-full` 로만)
   는 비발산 셀에서 **복구 안 함과 동일** (33 셀 동일 포즈), 원래 발산하는 셀에서는 섞임. → 지금 근거로는 켤 이유 없음
   (실제 무너짐에서의 효과는 무너짐 분석 보류로 미확인).

## 플래그 (ov_bridge, 전부 기본 꺼짐)
| 플래그 | 하는 일 |
|---|---|
| `--init-still 0|1` | ovpatch/VioManagerHelper.cpp: ZUPT 꺼진 채로 wait_for_jerk=false (정지 중 초기화). **비추천** |
| `--health 0|1` | 포즈 줄에 `"h":{state,tracked,used,chi2_rej,msckf_*,slam_*,delay_ok,pos_std,vel_std,ori_std_deg,since_upd,lost_run[,init_ready]}` |
| `--health-log FILE` | 같은 내용 CSV (프레임당 1 줄, + init_ready, acc_std) |
| `--health-cfg k=v,..` | 판정 기준 (기본 upd 0.2/1.0 s, std 0.25/1.0 m, trk 40/10 (15 프레임), rej 0.5) |
| `--recover N` | LOST N 프레임 + 영상 복귀 뒤 N 프레임 갱신 없음 → 옛 상태 주입 (같은 좌표계, num_pts 추적) |
| `--recover-full 0|1` | (v2 기본 꺼짐) 상태가 망가졌거나 간격 > `--recover-max-gap` → 전체 리셋 + 4-DoF 좌표 이어 붙이기 (`seg`, `frame_off`) |
| `--recover-max-gap S` / `--recover-min-feats N` | 3 s / 20 |
| `--test-blank T0:D,..` | 시험 전용: 첫 프레임 뒤 T0 s 부터 D s 동안 검은 영상 |
판정: LOST = 상태 비정상(NaN·속도 > --max-speed) 또는 영상 갱신 없음 > 1 s 또는 pos_std > 1 m 또는 추적 < 10 이 15 프레임;
DEGRADED = 갱신 없음 > 0.2 s, pos_std > 0.25 m, 추적 < 40, chi2 거부 > 50 %. pos_std 에는 초기화 때 고정 0.087 m 가 들어 있다.
`init_ready` (초기화 전): 최근 init_window_time 동안 가속도 표준편차 < init_imu_thresh (두 반쪽) 이고 추적 ≥ 15 → 다음 움직임에서 초기화됨.

앱 (빌드·설치 안 함, 통합 에이전트 몫): intent `ov_health 1` (→ `--health 1 --health-log <run>/health.csv`), `init_still 1`, `recover N`
(OvRunner.java / MainActivity.java, javac 확인). `tools/ov_phone_timing.py`: run 폴더에 health.csv 가 있으면 요약
(상태 비율·구간별·전이·가장 긴 LOST·첫 OK·추적/사용 점·chi2·pos_std·복구 횟수 + stderr recover 줄), `--health-csv FILE` 단독 요약.

## 위험 / 모르는 것
- `--recover` 효과는 합성 끊김에서만 봄. 실제 무너짐(정지 중 점 0 등)에서의 효과는 미확인 (무너짐 분석 보류).
- 상태 판정 기준값은 정함 (튜닝 안 함). 정지 중에는 영상 갱신이 없어 LOST 로 뜰 수 있음 (현재 방식 초기화 뒤 정지 = 실제로 IMU 만 적분).
- S1 의 0.5 m 튐에서 health 는 OK 였다 → health 는 "갱신이 끊김" 은 잡지만 "잘못된 갱신" 은 못 잡는다.
- `--reinit-state` (기존, lens2 live preset) 에도 같은 "주입 뒤 50 점" 문제가 있다 — 기존 동작이라 안 고침 (기록만).
- init_ready 가 1 이어도 이륙 움직임이 0.5 s 안에 시차 22.5 px 를 넘어야 초기화된다 (드론 이륙에서 미확인, 가정).
- `files/ov/live_stream.bin` 을 4.34 GB 정지 스트림으로 덮어씀 — 원래 10-18 파일(268 MB)은 `live_stream_20261018_kept.bin` 으로 복사해 둠. 지우지 않음.
- 폰 충전 상태: battery_start.txt 의 현재값은 "AC powered: false" 인데 같은 파일 이벤트 기록은 ac:true — 충전 여부 불명확 (위 "16:51 부터 충전" 은 코디네이터 공지 기준).
- 하지 않은 것: BLR1 v1 (중단), SIR (정지 출발 + 복구, 중단), P1 C (init_still raw80) 는 돌았지만 분석 안 함 (사용자 중단 지시).
