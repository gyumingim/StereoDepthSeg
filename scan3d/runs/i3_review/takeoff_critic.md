## 결론 먼저
1. "이득 확인 안 됨" 은 **규칙상 맞지만 i3 에 대한 반대 근거가 아니다.** 판정을 막은 것은 (ii) "녹화 ≥ 2" (무너짐 현상이 있는 녹화가 214550 하나뿐이라 처음부터 통과 불가) 와 (iii) 모은 중앙값의 구조다.
2. **(iii) 실패는 상당 부분 지표 구조 탓.** i3 중앙값 2.28 은 (2.203 + 2.356)/2 인데 2.203 은 i3 가 **막은** 214550_s0_d5 칸 (base 44.3 cm) 이다.

   - base 무너짐 칸(214550 3 개)을 빼면 base 1.517 / i3 1.66, 한계 1.717 → **통과**.
   - 단 진짜 악화 신호도 있다: i3 가 작동한 비-214550 칸 5 개 중 3 개가 +0.9–1.5 cm (213341 d1/d5 축척 0.92→0.83, 215348 d5). 같은 213341 이 B′b L6/L3 에서는 i3 가 좋아짐 (1.67→1.50, 1.77→1.51). 크기는 z2_isolate 에서 잰 시작 위치 민감도 (±0.25 s 로 0.1–0.8 cm, 한 묶음 0.93–1.76) 의 가장자리 → "작은 악화 가능성, 미확정".
3. **B′ 의 "0 막음" 도 지표 탓이 크다.** 이진 문턱(10 cm) 이 연속 이득을 지운다: B′a 214550 o0–o2 출발 뒤 10 s ATE base 3.7/2.8/3.3 → i3 0.69/0.59/0.81 cm (4–5 배, 축척 0.81–0.89 → 0.96–0.99). 문 밖 214550_L6/L3 도 58/35 → 7.3/3.4 cm. 214550 에서 i3 가 이긴 칸 = 8/9 (d1 은 66.9→10.9 로 크게 줄었지만 문턱 밖).
4. **B′b 설계는 미리 알 수 있는 실패였다.** strict 정적 초기화 + 동적 초기화 끔이면 움직임 중 시작한 클립은 정지에 들어가야 초기화된다 → 문 통과 2/8 (213955 만). 문은 base 만 보므로 B′ 커밋 전에 base 8 실행만 먼저 돌려 확인할 수 있었다. 편향 문제는 아니고 실행 낭비.
5. **근본 원인 후보는 i3 보다 ZUPT 시차 문턱 쪽이다 (추정).** 그리고 이 문턱은 214550 만의 문제가 아니라 **모든 녹화에서 여유가 얇다**:
