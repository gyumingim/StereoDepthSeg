카메라 없이 폰에서 녹화를 다시 넣어 본 NPU 루프 시험 전부 미검증

결론

  • 카메라 없이 폰 앱 안에서 녹화를 다시 넣는 재생 모드를 만들어 (0.6.35, intent replay), NPU 를 실제 앱 프로세스에서 켜고 끈 A/B 를 했습니다. 카메라는 한 번도 안 켰습니다 (매 run 뒤 카메라 클라이언트 [] 확인).
  • 루프 보정 정확도: 차이 보이지 않음 (사전 등록 판정). GT 녹화 3 개에서 NPU 쪽이 2 번, BRIEF 쪽이 1 번 나았고 차이는 0.01–0.07 cm 입니다. 추가 녹화 2 개까지 5 개 중 NPU 3 · BRIEF 2. 이 짧은 보드 앞 녹화들에서는 NPU 루프가 뚜렷이 낫지 않습니다 추정.
  • VIO 자체는 NPU 켬/끔 모두 같은 값입니다 (VIO ATE 165506 2.092 cm 등, 모든 run 동일). VIO 처리 시간과 온도 차이도 작습니다 (AP 최대 중앙값 NPU 50.2 / BRIEF 49.2 °C, 10 run 씩).
  • 앱 속이 느렸던 이유 3 가지를 찾았습니다: ① NPU 서버가 작은 코어 0-3 에 묶임, ② ENN 성능 모드를 안 부름, ③ 느린 CPU 후처리 코드. 고친 뒤 키프레임당 XFeat 35–38 → 10 ms, 상호 NN 85–90 → 6 ms, LighterGlue 52–56 → 17 ms (키프레임 중앙값, 서버 안 총시간, 0.6.34 설정 2 회 vs 0.6.36 기본 2 회). 짝 수·루프·ATE 는 그대로.
  • 이 설정을 0.6.36 (vc 45) 의 npu_loop 1 기본값으로 넣어 폰에 설치해 두었습니다. npu_loop 0 (기본) 동작은 바뀌지 않았습니다 (D0 = B run 과 같은 값). 되돌리려면 0.6.35d / 0.6.34 APK (같은 인증서).
