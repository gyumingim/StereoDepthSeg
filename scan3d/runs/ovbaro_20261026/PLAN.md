## 2. 무엇을 기대하나 (정직한 목표)
- 기압계는 정상 추적 중 VIO 높이를 더 좋게 만들지 못한다 (변동 ±20 cm > VIO 오차). 목표는
  (a) 정상일 때 **손해 없음** (포즈 차이 mm 이하),
  (b) VIO 높이가 크게 틀어질 때 (영상 끊김·IMU 만 전파·발산) 높이를 **수십 cm 안으로 묶기**,
  (c) 문 닫힘 같은 1–2 hPa 계단, 프롭 바람 같은 순간 교란이 출력에 **수 cm 넘는 튐을 만들지 않기**.

## 3. 설계 — 강결합 EKF 갱신 (브리지 안, OpenVINS 공개 API 만 사용)
선택: OpenVINS 필터에 직접 z 갱신. ovpatch 소스는 안 고침 — `ov_bridge/main.cpp` 가 프레임 갱신 직후
`StateHelper::EKFUpdate` 를 부르고, 기압 편향 2 개를 상태에 덧붙인다 (SLAM 특징을 덧붙이는 것과 같은 방식).
이유: (1) 출력이 pose / pred 스레드 / MAVLink / VIOP 네 갈래라 출력 쪽 보정 (느슨한 결합) 은 네 곳을 다 고쳐야 하고
필터 내부 (속도·바이어스) 와 출력이 어긋남; (2) 강결합이면 속도까지 고쳐져 IMU 예측도 같이 좋아짐;
(3) OpenVINS 패치 없이 공개 함수만 써서 침습이 작음; (4) 꺼짐 = 함수 호출 자체가 없음 → 포즈 비트 동일.
위험: 교란이 필터에 들어가면 되돌릴 수 없음 → 아래 게이트로 막음.

측정: `h = (R·T/g)·ln(p0/p)` (p0 = 첫 표본, T = 20 °C 기본) = 시작 기압 기준 상대 높이.
모델: `h = p_z(t_b) + b_c + b_g + n`, `p_z(t_b) ≈ p_z + v_z·(t_b − t_state)`.
- `b_c` = 느린 편향 (날씨·온도), 랜덤워크 `rw` (기본 0.0065 m/√s ≈ 1 분에 5 cm),
- `b_g` = 실내 기압 변동, Gauss-Markov (σ 0.25 m, τ 10 s) — 실측 Allan 에서,
- `n` 흰 잡음 σ 0.02 m (실측 1.3 cm + 여유).
처음 받아들이는 표본에서 `b_c = h − p_z` 로 잡음 (p 는 안 움직임).

게이트 (표본마다 상태 기록, `--baro-log`):
1. 초기화 전 / 초기화 뒤 `settle` (2 s) 동안 / lost → 안 씀.
2. |v_z| > `vz_max` (1.5 m/s) → 안 씀 (동압·지연 오차).
3. `ground_m` > 0 이면 이륙 높이 + ground_m 아래에서는 안 씀 (지면 효과; 손 시험은 0 = 끔, 드론 권장 0.3 추정).
4. 계단 검출: 혁신이 표본 사이 `step_jump` (0.15 m) 넘게 갑자기 바뀌면 STEP 상태 → 갱신 멈춤.
   혁신이 다시 chi2 를 통과하면 (2 표본) 복귀 (짧은 프롭 바람). `reanchor` (1.5 s) 넘게 계속되고 혁신이 안정되면
   `b_c` 만 옮겨 다시 묶음 (문 닫힘 = 영구 계단) → p 는 안 움직임.
5. 천천히 커진 큰 혁신 (chi2 > 9) → Huber 갱신 (R 을 키워 한 표본의 당김을 제한) — VIO 높이 표류를 천천히 끌어옴.
재초기화 (reinit/recover/reset) 로 VioManager 가 바뀌면 편향을 새로 잡는다.

## 4. 입력 경로
- 프로토콜 새 레코드 type 7 BARO: `<qd` t_ns (센서 시계 = IMU), 기압 hPa (16 B). `--baro 0` (기본) 이면 받아서 세기만 함.
- 앱 (arlat OvRunner): 인텐트 `baro 1` → TYPE_PRESSURE 등록 (80 ms), type 7 로 브리지에 보냄, `--baro 1` 전달, run 폴더에 `baro.csv`.
  HsRecorder: 인텐트 `hs_baro 1` → `imu.csv` 에 type 6 행 (형식은 이미 있음). 기본 꺼짐 = 등록 안 함.
- PC 시험용: `--baro-csv FILE` (t_ns,hPa; IMU 시각이 지나면 표본이 "도착") — 실시간과 같은 순서.
