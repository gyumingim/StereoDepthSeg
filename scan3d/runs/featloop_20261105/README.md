## 0. 시작 전에 이미 아는 것

  BA 는 끝에 VIO 중심으로 Sim(3) 정렬 → **축척은 VIO 몫**: 특징·루프를 바꿔도 축척 k 는 거의 안 바뀔 것 (예상, 미측정).

  즉 VIO 가 맞는 한 "다시 온 곳" 짝은 이미 들어 있음. 루프 검색이 더하는 것은 VIO 기준으로 멀거나 각이 큰 짝, 또는 10 개 한도 밖의 짝뿐.
- 삼각측량은 VIO 자세로 하고 재투영 4 px 넘는 관측은 버림 → VIO 가 크게 틀린 루프 관측은 BA 에 못 들어감 (구조상 한계, 그대로 둠).

## 3. 채점 (scanA 와 같은 자, 네 변형에 같게)
녹화마다 (`fl_score.py` 가 모음):
- C1 보드 모서리 자 (`corner_eval.py`, GT 자세 안 씀, 칸 크기만; H 용으로 보드 모양 일반화 = 9×5 칸 → 안쪽 모서리 8×4, 240 fps 행은 `--tol-ms 1 --max-gap-rows 1200` = 5 s):
  2시점 모양 RMS 중앙 / p90 mm, 2시점 |축척| 중앙 %, **다시점 재투영 중앙 / p90 px**, 다시점 축척 %.
- C2 보드 깊이 (`scan_offline.py` 960×540, FFS·TSDF 5 mm, BA 자세, 축척 그대로 = 실제 스캐너 상황): 전체 화소 dZ 평균 / p10 / p90 cm, **|dZ| p90**, 메시 보드 z 중앙 / RMS,
  평가된 키프레임 수. H 는 `--compress --kf-step 1` (scanA more 와 같음).
- C3 축척 k = BA 키프레임 자세 → GT Sim(3) 축척 (scan_offline `sim3_scale_would_be`) 과 SE3 ATE (cm).
- C4 개수: 짝 (기본 / 루프), 검증된 짝, 인라이어 중앙, 트랙, 점, 관측, 트랙 길이, 루프 짝이 이은 점·관측.
- C5 시간: 특징, 매칭, BA, 전체 (s), GPU 단계 시간.

## 4. 판정 (사전 등록)
- 주 지표 두 개: **C2 |dZ| p90** 과 **C1 다시점 재투영 p90**. 녹화마다 (변형 − S) / S 상대 변화.

  두 지표 모두 중앙값 ≥ +10 % 이고 ≥ 8 개에서 늘면 → "나빠짐". 그 밖 → "잡음 수준 (차이 없음)".
- 165506 은 따로 적음 (렌즈·fps·보드가 다름; 녹화 1 개 = 판정 근거 아님).
- 시간·개수는 판정에 안 넣고 적음. 권고는 판정 + 시간으로 정함 (같은 정확도면 빠른 쪽).
