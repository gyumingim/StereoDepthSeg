## 방법 (입력, 같은 자)
- 러너 `ov60_run.py` = `runs/integ_20261025/ate_run.py` 프로토콜 그대로 + fps 30/60 + 묶음 인자. 960x540, pts 200, init 창 1.0 s / 22.5 px,
  `num_opencv_threads=1,try_zupt=false,fi_max_cond_number=1e6,fi_max_baseline=200`, 레버, 프레임 캐시, strict init, 녹화별 R_ci/dt.
  벤치는 240 fps HS 녹화에서 1/fps 시간 격자에 가장 가까운 프레임을 고름 (std60 은 60 fps 원본).
- 브리지 = 이 브랜치 PC 빌드 (`ov60eval-20261026` = integ 14de3b8, 코드 변경 없음, `-DOV_FULL_SOURCE=ON`), sha256 bfb09392…, 고정 사본 `/tmp/ov60eval/ate/bin`.
- **`--drop-late 0` 을 묶음 뒤에 붙임**: drop-late 는 벽시계 기준이라 오프라인(속도 조절 없음, PC 공유)에서는 프레임을 비결정적으로 버릴 수 있음.
  나머지 묶음 요소(W3 정확/근사 수학, idle spin, health, predict 2 @200 Hz + 예측 스레드)는 포즈를 안 바꾸거나 시간만 바꿈 (integ 동일성 검사).
- 결정성: 5칸 (214550_o0·133820_o0 × P60·L60, 154320_o0_P60) 다시 돌려 포즈 해시 5/5 같음 (`/tmp/ov60eval/rep`).
- PC 시간(`pc ms`)은 PC 가 다른 역할 작업으로 부하 40 이었으므로 **시간 근거로 쓰지 말 것** (폰 시간은 ovpipe/ovupd 몫).
