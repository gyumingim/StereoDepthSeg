# 60 fps 촬영 → 15 fps 저장 (앱 1.8-subsample) 실측 기록

목표 (사용자 결정 2026-10-18): 60 fps 로 찍고 1/4 만 저장해 두 렌즈(2·5) 시각차를 최대 8.3 ms 로 줄이고,
녹화 용량·인코더 부담은 15 fps 수준으로 유지. 구현은 SPEC.md 1.2.3, 시험 도구 `scan3d/tools/subsample_test.ps1` +
`scan3d/tools/subsample_ana.py` (시험 녹화는 결과를 뽑은 뒤 폰·PC 에서 지움).

## 1. 90 s 비교 (2026-10-18 13:36~13:40, 실내 같은 자리, 폰 정지, 1440x1080 렌즈 2+5, mode both, 14 Mbps, 앱 1.8 최종 빌드)

| 항목 | 15 fps 기존 모드 | 60 촬영 / 15 저장 |
|---|---|---|
| 카메라 결과 /s (렌즈별 cam_fps) | 15.0 (15 / 15), 건너뜀 0 | 48.6 (48.6 / 48.6), HAL 이 5~6 장마다 한 장씩 건너뜀 (1016 장) |
| 저장 fps (렌즈 2 / 5 프레임 수) | 15.0 (1407 / 1407) | 15.0 (1404 / 1403) |
| 저장 짝 시각차 (노출 가운데) | 중앙 31.7 · p95 33.2 · 최대 33.3 ms (그 세션 위상) | 중앙 4.8 · p95 13.2 · 최대 16.5 ms (짝 1404, 짝 없음 1) |
| 노출 (중앙) | 33.4 ms (렌즈 2 는 16.7~41.6) | 16.7 ms (60 fps 상한에 붙음) |
| 폰 CPU (앱 전체, 한 코어 %, 중앙) | 158 % | 180 % (+22 % → 0.48 %/촬영 fps) |
| 복사 시간 (남긴 프레임, 렌즈당) | 6.3 ms | 8.1 ms |
| 배터리 온도 | 37.4 → 39.2 °C | 39.2 → 39.8 °C (바로 이어서 돌림) |
| thermal_status / headroom | 2 / 0.90 → 0.99 | 2→3 (64 s 부터) / 0.96 → 1.03 |
| 녹화 비트레이트 (렌즈 2 / 5) | 13.9 / 14.0 Mbps | 13.9 / 14.0 Mbps |
| 녹화 용량 | 210 MB/분 | 210 MB/분 |

- 발열: 폰이 처음부터 따뜻했고(37.4 °C, status 2) 두 시험을 이어서 돌려 headroom 이 두 시험 내내 비슷한 기울기로 올랐다
  (90 s 당 +0.09 / +0.07). 60/15 에서 status 3 이 된 것은 이어서 돌린 탓이 커 보이나 확실히 가르지는 못함. 온도 상승은 60/15 가 더 작았다.
- 같은 세션 짧은 시험(10 s)에서는 15 fps 위상이 14.6 ms (카메라를 열 때마다 바뀜, 예전 기록 10~33 ms), 60/15 는 중앙 5.0 ms.
- 처음 15 s 시험 (11:25, 복사 개선·격자 유지 전 빌드): 저장 14.2 fps, CPU 196 %, 복사 20 ms — 지금 빌드에서 고쳐짐.

## 2. 어두운 실내 노출·잡음 (10 s 씩, 같은 자리 — 사용자 없이 조명은 못 바꿈, 이 자리가 이미 어두운 편: 15 fps AE 가 33 ms 씀)

| 렌즈 | 모드 | 노출 | 밝기 (Y 평균) | 시간 잡음 (연속 프레임 차 std/√2) | SNR |
|---|---|---|---|---|---|
| 2 (초광각, VIO) | 15 fps | 33.4 ms | 110 | 1.76 | 63 |
| 2 | 60/15 | 16.7 ms | 89 | 3.47 | 25 |
| 5 (광각) | 15 fps | 33.4 ms | 95 | 2.82 | 34 |
| 5 | 60/15 | 16.7 ms | 88 | 2.96 | 30 |

- 60 fps 는 노출이 16.7 ms 를 못 넘어 어두운 곳에서 렌즈 2 잡음이 약 2 배 (H.264 를 거친 값). 대신 움직임 번짐은 절반.
- 밝은 곳(15 fps 에서도 노출 ≤ 16 ms)에서는 차이가 없을 것으로 봄 (추정, 안 잼).

## 3. 결정
- `scan3d.py CAPTURE_FPS_DEFAULT = 60` (기본 60 촬영 → 15 저장): 시각차가 확실히 작아짐 (중앙 15~32 → 4.8 ms), CPU +22 %(한 코어)는
  10 코어 폰에서 감당, 발열 차이 뚜렷하지 않음. 어두운 곳에서 잡음이 문제면 웹 [촬영: fps 그대로] 로 바꾼다.
- `load_model.PHONE_CAPTURE_PCT_PER_FPS = 0.48` (predict 의 phone_capture_pct; 복사 한계 검사와는 따로 — 섞으면 기본값이 늘 '부하 높음').

## 4. 남은 것
- 실제 움직이며 녹화 → 복원(replay) 으로 깊이·VIO 품질 비교 (움직임 보정 dt 가 줄어든 효과 대 잡음이 늘어난 효과).
- 실시간(USB) 스트림으로 60/15 를 PC 가 받는 것 끝까지 (이번에는 녹화 + 공유 인코더 출력 15 fps 만 확인, 무선 adb 라 스트림 못 받음).
