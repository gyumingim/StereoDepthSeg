C5 재시험: 정지가 짧으면 초기화 설정이 중요한가 (2026-10-21)

정정 안내 (2026-10-21 오전): 읽기 전용 검증(docs/c5_retest_verify.md)과 정답 칸 크기 변경(40.70 → 42.72 mm, 노트북 사양 계산, 추정)을 반영해 아래 결론에 (정정 …) 을 달았다. 지운 문구는 줄을 그어 남겼다. 표와 그림은 40.70 mm 정답으로 만든 그대로다 (실행 판정은 아래 7번 정정만 바뀜). 드론 권고(loose, 정지 2 s 이상)는 그대로이지만 조건이 붙는다.

결론 먼저 (모두 추정 — 녹화 5개)

답: 그렇다. 정지가 짧으면 초기화 설정이 결과를 크게 바꾼다. 밤샘(정지 10~18 s)에서는 같았던 strict 와 loose 가, 정지 1~3 s 에서는 갈렸다.

  2. strict 의 실패는 무너짐이 아니라 '초기화 안 됨'이다 (25개 전부). 로그를 보면 (추정) 화면 정지 문턱 2.24 px(0.3°)이 너무 빡빡하다: 221052 는 정지 중에도 시차가 2.9 px 이상이라 '정지'로 인정 안 됐고, 움직이기 시작하면 strict 는 동적 초기화가 꺼져 있어 60 s 동안 다시 기회가 없다. loose 의 문턱은 15 px.
    (정정 2026-10-21 오전, 검증 docs/c5_retest_verify.md: 원인은 문턱이 빡빡해서가 아니라 주로 시점이다 (추정). S = 1 s 에서는 정적 판정 창 1.5 s 가 남은 정지 1 s 보다 길어 첫 판정 때 이미 움직임이 창에 들어간다 (223815·224323 시차 8~47 px). IMU 를 2 s 먼저 넣으면 12 → 4 로 줄어드는 것도 시점 문제라는 뜻이다. 221052 는 '정지' 중에도 화면 시차가 5.6~16 px 로 화면상 정지가 아니었다 — 문턱을 조금 풀어서는 통과 못 하고, loose(15 px) 라서 통과했다. '2.9 px' 는 분석 코드가 계산한 값이 아니라 로그 한 줄(221052_S3_strict_d0)의 값을 손으로 쓴 것이다. 문턱 바로 위(2.3~2.6 px)에서 실패한 것은 222747 S2 와 214138 S1 d0 뿐.)
  3. 보조 (IMU 를 2 s 먼저 넣으면, S = 1): loose 0/15, strict 4/15 초기화 안 됨, strict-dyn 2/15 무너짐. IMU 가 카메라보다 먼저 돌고 있으면 strict 도 대부분 초기화된다(12 → 4).
  4. 밤샘 결론 정정 범위: '정지 10 s 이상에서 strict = loose' 는 그대로. 새로 안 것 = 정지 1~3 s 에서는 strict 가 가장 자주 실패(초기화 안 됨).

  • 설정 제안 (미시험, 다음 시험 후보): 정적 초기화만 쓰되 시차 문턱을 loose 처럼 15 px 로 푼 설정 (= loose 에서 동적 초기화 끔). 이번 결과로는 정적 초기화가 되기만 하면 안전했고, strict 의 문제는 문턱이 빡빡한 것이었다.
