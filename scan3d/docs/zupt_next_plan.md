  기존 데이터 예비 A/A (3 반복) 는 이미 10 % 를 크게 넘었다 (`docs/zupt_next_prep.md` 4) → 문턱 재조정이 필요할 가능성이 높다 (추정).

## 2. 규칙 (judge.md 4 절, 앞으로만 적용)
0. **선행 (끝남)**: GT 카메라 중심 c = p_bc 로 고친 스크립트 커밋 9a73b85. 진짜 정지 ZUPT 수·1 s 상대 오차 다시 냄 (보고만).
1. **묶음**: 실행 전에 입력 사건 검출기 (`imu_learn/input_events.py`, 4 g / 자유낙하 0.1 s, 문턱 그대로) 를 모든 녹화에 돌린다.
   걸린 녹화는 **충격 묶음**: 정확도 기준에서 빼고, "건강 표시가 충격 뒤 3 s 안에 나빠짐을 내는가" 와 발산 run 수만 보고한다.
   원시 IMU 가 없어 검출기를 못 돌리는 녹화는 판정 데이터에 넣지 않는다 (새 녹화는 모두 원시 IMU 를 기록).
2. **채점 창**: 첫 추적 포즈부터 min(마지막 유효 GT 표본, 녹화 끝 − 3 s) 까지. 창 밖 사건은 보고만.
3. **반복**: 녹화당 오프셋 5 개 (0, 1, 2, 3, 4 s).
4. **A/A 시험 (본 시험 전)**: base 를 두 번째 오프셋 묶음 (0.5, 1.5, 2.5, 3.5, 4.5 s) 으로도 돌려, 한쪽을 "후보" 로 놓고 아래 기준 2·3 으로 양방향 채점한다.
   오탐률 = (기준 3 에서 실패한 녹화 수 / 녹화 수) 와 (기준 2 에서 실패한 묶음 수 / 묶음 수). 둘 중 하나라도 10 % 를 넘으면 문턱을 고쳐 **다시 커밋** 한 뒤 본 시험.
   A/A 는 새 녹화의 base 만 쓴다 (후보 run 은 A/A 문턱 확정 커밋 뒤).
5. **사건 짝짓기**: 녹화 절대 시각 ±1 s, 같은 녹화의 모든 base 오프셋과 비교. 어느 base 오프셋에도 없을 때만 "새 사건".
6. **발산 (GT 기준)**: 채점 창 안 아무 5 s 창의 상대 오차 > 30 cm 또는 창 ATE > 50 cm. 전멸 수는 보고만.
   - 5 s 상대 오차 = 창 안에서 위치를 GT 중심에 SE3 로 한 번 정렬한 뒤, 0.1 s 격자에서 |(p(t+5) − p(t)) − (c(t+5) − c(t))| (GT 양 끝 20 ms 안 유효 표본이 있을 때만). 구현: `imu_learn/zupt_aa.py` 의 `metrics()`.
7. **기준 1 (막기, 호버)**: 표적 run 발산 0. **ZUPT 연속이 끝난 뒤 1 s 안** 의 전부 거절·전멸 0. ATE 한계: 133820 ≤ 10 cm, 134550 o2 ≤ 5 cm (개발 데이터용), 새 반정지 녹화는 ≤ 5 cm (base 134204 수준).
8. **기준 2 (새 발산 없음)**: 묶음별 후보 발산 run 수 ≤ base, 그리고 "base 는 오프셋 과반이 멀쩡한데 후보는 과반이 발산" 인 녹화 0.
9. **기준 3 (회귀 없음)**: 녹화별 오프셋 중앙값으로 5 s 상대 오차 p95 ≤ base × 1.1 + 0.5 cm, 창 ATE ≤ base × 1.2 + 0.5 cm.
   진짜 정지 (고친 GT 속도 < 0.05 cm/s, ±0.25 s) ZUPT 수 ≥ base 의 90 % (base ≥ 30 인 녹화만).
10. **기준 4 (기전)**: 표적 반정지 안에서 일반 갱신 간격 < 0.72 s. 유지.
11. **보고만**: 이륙 지표 (시작 정지 뒤 첫 움직임부터 3 s 최대 오차), 누적 검사 실패 수 (특징 ≥ 10 첫 갱신 전·후 나눠서), GT 속도 > 10 cm/s 인데 ZUPT 수락된 프레임 수, 1 s 상대 오차.
12. **판정 데이터**: 3 절의 새 녹화만. 이 문서 커밋 전에는 새 녹화의 VIO 를 돌리지도 열어보지도 않는다.

### 판정
- 채택 = 기준 1–4 모두 통과. A2 와 A2b 가 둘 다 통과하면 기준 3 의 5 s p95 (녹화 중앙값의 중앙값) 가 낮은 쪽, 같으면 (차이 < 0.2 cm) A2 (더 단순).
- 기준 1 실패 → 기전 재조사. 기준 1 통과·2/3 실패 → 실패 사례 조사 뒤 새 후보를 다시 사전 등록 (이 데이터는 그때 개발용이 됨).
- 반복 수 (5), 섞인 변수 (A2 → A2b 는 면제 조건 하나) 를 결과 문서에 적는다.

## 3. 새 녹화 프로토콜 (이 문서 커밋 뒤에만 찍고 돌림)
1. 호버 흉내 반정지 (손 움직임 중간 0.5–3 cm/s, 2–10 s) 6 회 이상, 보드 거리 2 가지 — 기준 1 의 판정 데이터.
2. 10 s 정지 뒤 빠른 이륙 (20–40 cm/s) 5 회 — 214550 o1 류 회귀 확인.
3. 30–60 s 진짜 정지 3 회 — 기준 3 정지 이득.
4. 빠르게 내려놓기 3 회 (133820 50.9 s 같은 사건), 보드 아닌 질감 많은 장면 3 회.
5. 가능하면 quad450 틀에 폰 + 모터 진동.
6. 녹화마다: fps ≥ 235 확인, 원시 IMU 기록 확인, 입력 사건 검출기를 먼저 돌려 묶음 배정. 녹화 끝 3 s 는 채점 안 함.
- 의도적 낙하는 찍지 않는다 (폰 보호). 충격 묶음은 기존 213955 로만 보고.
