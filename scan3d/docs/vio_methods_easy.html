VIO 방식 한눈에 — 드론이 "내가 어디 있지?"를 아는 법

VIO = 카메라(눈) + IMU(속귀). 눈은 정확하지만 느리고 가끔 못 보고, 속귀는 빠르지만 조금씩 틀어집니다. 둘을 합치는 방법에 따라 이름이 갈립니다.

0. 공통 원리 — 눈과 속귀

카메라는 벽·바닥의 특징점(무늬 모서리)이 사진마다 어디로 갔는지 보고 움직임을 계산합니다. IMU는 사진 사이의 빠른 움직임을 메웁니다. 둘이 서로의 실수를 잡아 줍니다.

1. 필터 방식 — OpenVINS (MSCKF)

OpenVINSMSCKF가벼움GPLv3

원리: 걸으면서 메모장 한 장만 들고 다니는 사람. 새 정보가 오면 메모를 고치고, 오래된 건 요약해서 버립니다.

장점 가볍고 빠름(폰에서 한 장 13 ms 측정), 수학적으로 꼼꼼(FEJ로 "모르는 걸 안다"고 착각 안 함), 보정값 실시간 추정 기능. 단점 지나간 실수를 못 고침, 오래 날면 조금씩 흘러감(루프 없음).

2. 묶음 최적화 방식 — VINS-Mono/Fusion, Basalt, DM-VIO

VINSBasalt (BSD)DM-VIO조금 더 무거움

원리: 최근 몇 초의 자세들을 구슬처럼 놓고 사진(실)과 IMU(고무줄)로 묶어 창 전체를 매번 다시 맞춤.

장점 필터보다 보통 조금 더 정확, 최근 실수를 고칠 수 있음. Basalt는 BSD라 상업적으로 쓰기 쉬움. 단점 계산이 더 많음, VINS는 ROS1 필요(우리 환경에 안 맞아 제외).

3. SLAM 방식 — ORB-SLAM3

ORB-SLAM3지도 + 루프 클로저무거움GPLv3

원리: 다니면서 지도(장소 사진 모음)를 만들고, 전에 본 곳에 다시 오면 알아채서(루프 클로저) 그동안 쌓인 오차를 한 번에 바로잡습니다.

장점 오래 날아도 덜 흘러감, 지도를 다음에 다시 쓸 수 있음. 단점 무겁고(스레드 여러 개), 단안+IMU 시작이 까다로움, 루프가 걸리는 순간 위치가 "툭" 바뀜.

4. 학습 IMU 방식 — AI-IO, AirIO, TLIO

카메라 없이 / 카메라 끊겼을 때연구 단계

원리: 신경망이 IMU 패턴에서 속도·이동을 추정해 필터에 넣습니다. 드론에선 모터 회전수를 같이 쓰면 훨씬 좋아집니다.

장점 어둠·빠른 회전처럼 카메라가 실패할 때 버팀. 단점 몇 초~십몇 초용, 학습한 상황(경로·기체) 밖에서는 약함. 이것만으로 자율 비행한 논문은 아직 못 찾음.

5. 단안 vs 스테레오

👁️ 단안 (카메라 1개)

장점 가볍고 간단. 단점 처음에 움직여야 크기(스케일)를 앎, 제자리 회전에 약함.

👀 스테레오 (카메라 2개)

장점 바로 시작, 정확·튼튼. 단점 처리 2배, 우리 폰은 렌즈 간격 1~2 cm(가까운 거리만), 동시에 찍히는 조합이 2·6번뿐.

우리 계획

연구·시험은 OpenVINS(가볍고 이미 폰·PC에 있음) + 비교용 ORB-SLAM3. 제품화가 필요해지면 Basalt(BSD)로 옮길 수 있게 연결부를 갈아 끼울 수 있게 만듭니다. 우리 기여는 VIO 본체가 아니라 IMU 보정·시간 맞추기·정답 도구, 그리고 카메라가 끊길 때 IMU로 버티기입니다.

근거: 2026 연구도 "정확한 사전 보정 + 같은 VIO에서 비교"를 권장(arXiv 2609.13777). 학습 IMU 단독 자율 비행은 아직 보고 없음(AI-IO 2026은 사람이 조종).
