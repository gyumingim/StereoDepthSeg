토론 결과 — 아주아주 쉽게

AI 두 명이 "우리 드론 프로젝트, 지금 하는 방식이 맞나?" 로 3번 주고받으며 토론했습니다.

비유로 먼저

자전거를 배운다고 해 봅시다.
A 는 "바퀴·브레이크·체인을 완벽하게 정비하고 타자" 고 하고,
B 는 "정비는 기본만 하고 일단 밖에서 타 보자. 넘어지는 이유는 타 봐야 안다" 고 합니다.
→ 결국 둘 다 "기본 정비만 하고 빨리 밖에서 타 보자" 에 거의 동의했습니다.

두 사람의 주장

🔧 A — 정비 먼저

"센서 값이 정확해야 위치도 정확하다. 원본 값 쓰고, 온도 보정하고, 정답도 정밀하게 만들자."

🚴 B — 일단 타 보자

"책상 위 점수만 올리고 있다. 진짜 드론에 달면 진동·속도·발열이 다르다. 빨리 폰을 드론에 달고 돌려 보자."

✅ 둘 다 동의한 것

  1. 점수는 "실제 위치를 얼마나 맞히나" 로만 매긴다.
    센서만 따로 떼서 재던 점수(0.99 cm)는 기준에서 뺀다. 그 점수가 좋아져도 실제로는 나빠진 적이 있어서.
  2. 복잡한 보정(27개 숫자)은 일단 끈다.
    녹화 하나에서 오히려 크게 망가졌는데 이유를 아직 모름. 이유를 찾을 때까지 보류.
    (정정 15:20: 이유 나옴 — 보정 탓이 아니라 시작할 때 위치 잡기(초기화) 실패. 보정을 안 넣어도 같은 녹화가 무너짐. 주된 후보는 시험대의 느슨한 초기화 설정이고, 엄격한 설정으로 다시 돌려 확인 중. 보정이 좋은지 나쁜지는 아직 판정 불가 — calib_vio_check.html)
  3. 센서 틀어짐은 간단하게 잡는다.
    "시작할 때 몇 초 가만히 두고 잰 값 + 온도로 고치기". 이 두 가지면 충분하다.
  4. 앱을 고친 다음, 진짜 드론 조건으로 찍는다.
    원본 센서 값 + 온도를 기록하는 앱으로. 모니터 앞에서만 찍지 말고 드론 틀에 달고 모터도 켜고.
  5. 카메라가 잠깐 가려지면 위치가 확 튀는 문제는 따로 고쳐야 한다.
    센서 탓이 아니라 "다시 위치 잡는 기능" 이 약해서 생기는 문제.

🤔 아직 의견이 다른 것

  • 복잡한 보정을 완전히 버릴지 — 실제로 비교해 보고 정하기로 함
  • 망가진 녹화가 코드 실수 때문인지 — 지금 확인 중 (오늘 낮) (정정 15:20: 확인 끝 — 보정 적용 코드 버그 없음, 원인은 초기화 실패)
  • 다른 위치 추정 프로그램(Basalt)을 언제 시험해 볼지

📅 추천 일주일 계획

① 망가진 녹화의 이유 찾기 (지금 하는 중 정정 15:20: 초기화 실패로 확인, 엄격한 초기화 시험 중)
② 폰에 새 앱 깔고, 원본 센서 값·온도가 잘 기록되는지 확인
③ 폰에서 직접 위치 추정을 5분 돌려 보기 — 폰이 제시간에 계산을 끝내는지
④ 폰을 드론 틀에 달고 모터 켠 채 녹화 3개 + 모니터 앞 녹화 2개
⑤ 세 가지 비교: 보정 없음 / 간단 보정 / 복잡한 보정 — 실제 위치를 누가 제일 잘 맞히나
⑥ 카메라가 1~3초 가려져도 위치가 30 cm 이상 안 튀게 고치기

②·④ 는 폰을 직접 만지셔야 합니다.

🧐 토론 중 틀린 말 (사회자가 잡음)

  • "1초에 60장이면 한 장당 33 ms 안에만 계산하면 된다" → 틀림, 16.7 ms 안에 끝내야 함
  • "시간 맞추기 버그 때문에 녹화가 망가졌다" → 아님, 그 버그는 영향이 0.2 mm 로 아주 작음
  • "녹화 3분에 15 °C 오른다" → 재는 곳마다 다름 (배터리 8~10 °C, 칩 약 15 °C)
