코드: runs/board_rotation_review/collapse_timeline.py → collapse_timeline.json (5 s 칸별: ZUPT 수락/거절, 초기화 실패, 추적 특징 수,

## 결론 (먼저)
- **VIO 실패다.** GT 는 정상 (자세 OK 0.983, 축척 0.996).
- 원인: **손 움직임 중간에 폰을 약 6 s 거의 멈춤** (VIO 시각 약 35–41 s, GT 속도 1–1.5 cm/s).
  그동안 ZUPT (정지 갱신) 가 계속 받아들여지고, 그 사이 일반 갱신이 한 번 돌 때 **SLAM 특징 약 48 개가 한꺼번에 0 개**가 됐다 (o0 37.0 s, o2 35.0 s).
  MSCKF 특징도 원래 0 개 근처였다. 다시 움직이기 시작한 41.5 s (o2 40 s) 부터는 **영상 갱신이 하나도 없이 IMU 적분만** 돌아 1 s 에 수십 cm 씩 튀어 수 m 로 발산.
  끝날 때까지 SLAM 특징이 다시 생기지 않았다 (65 s 까지 0).
- 그 시각에도 영상 추적은 정상이었다: ZUPT 판정용 추적 특징 155–170 개, 움직일 때 시차 5–20 px. 즉 **화면에 특징이 없어서가 아니라 필터가 특징을 다 버린 것**.
- **대조 134550 o2 도 같은 방식으로 무너졌다**: 47–50 s 정지 (ZUPT) → 51 s SLAM 38 → 0 → IMU 만으로 약 0.5 m 튐 → 54 s 에 SLAM 50 개로 다시 잡히며 위치 점프 (ATE 18.5 cm).
  같은 녹화의 o0, o1 은 그 정지 뒤 SLAM 이 40 개 안팎으로 유지돼 살아남았다. 134204 는 손 움직임 중간 정지가 없었다 (10–50 s ZUPT 수락 0).
- 따라서 **보드 회전·거리 탓이 아니다.** 거리 0.68 m 는 134204 (0.66 m) 와 2 cm 차이. 회전 녹화가 계속 무너질 이유는 아니고, **"중간에 멈추지 않기"** 가 대책이다.

## 왜 SLAM 특징이 한꺼번에 사라지나 (추정)
- OpenVINS (src/open_vins/ov_msckf/src/core/VioManager.cpp 약 297–306 행) 는 ZUPT 가 받아들여지면 그 프레임에서 바로 return 한다 (클론 추가·특징 갱신·특징 DB 정리 없음).
  SLAM 특징은 특징 DB 에서 찾을 수 없으면 (`feat2 == nullptr`) 버려진다 (같은 파일 약 473 행). 긴 ZUPT 와 일반 갱신이 섞이는 동안 SLAM 특징의 추적 기록이 끊겨 한 번에 버려지는 것으로 보인다.
  설정상 zupt_chi2_multipler = 0 (시차 0.5 px 미만이면 무조건 수락) 이라 손을 거의 멈추면 ZUPT 가 길게 이어진다. 코드 경로를 끝까지 따라가 확인하지는 않음 (추정).
- 133820 은 처음부터 MSCKF 특징이 0 개 근처 (134204 는 2–8 개) 였고 손 움직임도 느렸다 (5–11 cm/s, 134204 는 16–32 cm/s). 그래서 SLAM 이 빠지자 대신할 갱신이 없었다 (추정).
