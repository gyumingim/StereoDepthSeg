# 초점 3 개에서 렌즈 보정 → 초점별 보정표 (2026-10-22)

**결론**
- 세 초점(3.33 / 1.00 / 0.37 dpt)을 같은 도구·같은 모델(rational)로 보정했지만, **보정값끼리의 차이가 보정 불확실성보다 크지 않다.**
  보드를 거의 정면으로만 찍어서(기울기 중앙값 8–14°) 초점거리 fx 가 잘 안 정해진다. 같은 0.37 dpt 를 다른 녹화(111605)로 보정하면 화면 배율이 −4.2 % 다르고(부트스트랩 구간 밖), 사진 120 장 대신 전부 쓰면 1.0 dpt 의 fx 가 −2.4 % 바뀐다.
- 그래서 **보정값으로 만든 표(`hs_1920x1080_focus_table.json`)는 쓰지 않는 것이 맞다.** 초점 바꾸기 영상(105441)에서 보상 뒤 남는 배율이 −0.54…+0.79 %, 위치 차이 1–4 px 로, 직선 k(0.008/dpt) 보상(0.00…+0.10 %)보다 약 10 배 나쁘다.
- 쓸 것: **`hs_1920x1080_focus_table_sweep.json`** (f2.22 보정값 + 같은 자세에서 잰 초점별 배율, 노드 4 개, 0.37 근처 비선형 포함). 단 이 표는 검증한 영상과 같은 영상에서 만든 것이라 검증이 독립적이지 않다.
- 주점(cx, cy)이 초점에 따라 움직이는지: 보정끼리는 3–6 px 차이지만 같은 초점 재보정 차이(6, 15 px)보다 작아 판단할 수 없다. 같은 자세 초점 바꾸기 영상에서는 직선 보상 뒤 보드 이동이 0.3 px 이하라서 **주점 이동은 0.5 px 미만으로 본다 (추정, 자세 1 개)**.
- 다음에 할 것: 보드를 30–45° 기울인 사진이 많은 보정 녹화(초점마다, 폰 고정·보드 이동 또는 천천히 돌리기)를 다시 찍으면 표를 보정값으로 채울 수 있다.

## 1. 보정 방법 (기존 렌즈 파일과 같은 도구)
- 기존 `config/lens/hs_1920x1080_f*.json` 은 `imu_learn/lens_calib.py` 가 만든다 (GT 파이프라인 `imu_gt.py` 가 렌즈 파일이 없으면 `lens_calib.calibrate([rec])` 호출).
  고르기: 자이로 |ω| < 0.3 rad/s 프레임, 모서리 20 개 이상, 화면 3×3 칸 × 기울기 3 구간에 퍼지게 120 장, 왜곡 모델 3 개 중 반쪽 검증 오차가 가장 작은 것, 사진 오차 2.5 배 넘는 것 빼고 다시 맞춤.
- 이번 추가 (같은 함수 `spread`, `fit`, `holdout_err` 사용):
  - 폰을 받침대에 놓은 구간(±0.5 s 동안 |ω| < 0.04) 사진 제외 — 녹화 앞뒤 4–6 s 가 받침대 구간이고, 0.37 dpt 녹화에서는 이 구간의 보드가 가까워 흐림(선명도 85–100 vs 손에 든 구간 1000+). 같은 자세 사진이 수백 장이라 부트스트랩도 속인다.
  - 선명도(보드 영역 라플라시안 분산)가 녹화 중앙값의 0.5 배 미만인 사진 제외.
  - 모델은 세 녹화 모두 rational 로 고정 (세 녹화 모두 반쪽 검증 오차 최저: 0.384 / 0.190 / 0.139 px; k1k2p 보다 0.01–0.03 px 좋음).
- 부트스트랩 300 번: 사진 단위(frame)와 1 초 묶음 단위(block; 붙어 있는 프레임은 자세가 비슷해 서로 독립이 아님). 아래 구간은 95 %.

## 2. 초점에 따른 변화와 유의성
같은 광선 → 화소 지도를 두 보정 사이에서 비교 (두 보정이 모두 덮은 화면 영역만), 배율 + 이동 + 나머지(왜곡 차이)로 나눔. 부호: 양수 = 가까운 초점(큰 dpt)에서 화면이 커짐.

| 비교 | 배율 차 / dpt (frame CI) | 배율 (block CI) | 이동 px (x, y) | 나머지 rms / 최대 px |
|---|---|---|---|---|
| 1.00 → 3.33 | +1.38 %/dpt (+0.74…+2.51) | 3.22 % [0.78, 7.08] | (−3.0, +4.0) | 1.08 / 5.1 |
| 0.37 → 3.33 | +1.22 %/dpt (+0.94…+1.56) | 3.62 % [1.59, 5.13] | (−5.7, −1.1) | 1.48 / 4.7 |
| 0.37 → 1.00 | +0.90 %/dpt (−4.0…+3.3) | 0.56 % [−4.10, 2.70] | (−2.9, −4.8) | 0.16 / 0.5 |
| **같은 0.37: 120556 → 111605** | — | **−4.23 % [−6.86, −1.77]** | (−6.0, −14.9) | 0.26 / 0.7 |
| 0.37 (120556) → 기존 f2.22 (131326) | −0.40 %/dpt | −0.73 % [−2.73, 0.68] | (−7.7, −7.8) | 1.05 / 4.3 |

- 같은 자세에서 잰 값(초점 바꾸기 영상, ±0.02 %): 0.37→1.0 +0.64 %/dpt, 1.0→2.22 +0.79, 2.22→3.33 +0.81, 전체 +0.77 %/dpt (k 0.0080 은 이 영상에서 나온 값).
- fx 차이: 3.33 대 나머지만 CI 가 0 을 넘지 않지만 크기가 같은 자세 측정의 1.5–1.8 배. 같은 초점 재보정 차이(−4.2 %)가 부트스트랩 구간 밖이므로 실제 불확실성은 부트스트랩보다 크다(보드가 정면이라 fx–거리 맞바꿈, 사진 고르기에 민감). **유의하지 않다고 본다.**
  - 사진 고르기 민감도 (rational, 120 장 → 전부): 3.33 1327.4 → 1322.1, 1.00 1280.2 → 1250.0, 0.37 1271.8 → 1264.4, 111605 1217.4 → 1200.4. 기존 렌즈 파일(같은 도구, 받침대 사진 포함): f0.37 (111605) 1301.9, f2.22 (131326) 1267.1.
- 주점: 이동 3–6 px 는 같은 초점 재보정 이동(6, 15 px)보다 작다 → 유의하지 않음. 같은 자세 영상에서는 0.3 px 이하.
- 왜곡: 3.33 대 나머지에서 나머지 1.1–1.5 px (3.33 녹화의 rms 가 0.44 로 가장 크고 선명도가 낮아 보정 품질 탓일 수 있음, 추정). 1.00 대 0.37 은 0.16 px, 같은 초점 재보정 0.26 px. **왜곡 변화도 이 데이터로는 판단 불가.**
- 왜곡 크기(자기 K 기준, 덮인 영역): 중앙 3–4 px, p95 12–19 px.

## 3. 보정표와 벤치 옵션
- `config/lens/hs_1920x1080_focus_table.json`: 위 세 보정값 (rational, 녹화·사진 수·덮음·부트스트랩 구간 포함). **권장하지 않음** (파일에 warning).
- `config/lens/hs_1920x1080_focus_table_sweep.json`: f2.22 의 K·왜곡에 같은 자세에서 잰 배율(0.37: ×0.98630, 1.00: ×0.99031, 2.22: ×1, 3.33: ×1.00900)을 fx, fy 에 곱한 노드 4 개. 주점·왜곡은 그대로. = 노드별 꺾은선 k.
- 보간: 노드마다 같은 출력 핀홀(Knew)로의 원본 화소 지도를 만들고, 프레임 초점 D 에서 양옆 노드 지도를 dpt 에 대해 직선으로 섞음 (= 투영을 보간; rational 계수 보간은 안 함). 노드 밖 D 는 끝 노드로 고정(clamp).
- `imu_learn/vio_bench_hs.py --focus-comp --focus-table <file>` (기본 꺼짐). 켜면 직선 k 대신 위 보간 지도로 프레임마다 왜곡 펴기. 원래 렌즈 파일 지도와 tol_px(0.05) 미만 차이면 원래 지도 그대로. 결과 JSON 에 focus_table, focus_table_dpt, frames_focus_clamped, table_map_shift_px_max 추가. `--focus-table` 만 주고 `--focus-comp` 가 없으면 종료.
- 표는 절대값이다: 녹화의 렌즈 파일(예: f0.37 = fx 1301.9)과 표의 K 가 다르면 표 쪽 K 로 편다 (VIO 가 받는 핀홀 Knew 는 렌즈 파일 그대로).
