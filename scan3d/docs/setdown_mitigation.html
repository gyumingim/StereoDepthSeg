결론 먼저 (모두 추정 — 녹화 2 개, 손으로 내려놓음)

설정 두 줄로 고쳐진다: zupt_chi2_multipler: 1 + zupt_noise_multiplier: 1 (Z2). 224323 의 마지막 정답 창 오차가 24.3 → 0.8 cm (중앙값, 위치 3 개), 끝 정지 이동이 40.4 → 0.26 cm, 전체 ATE 5.03 → 0.69 cm. 223815 와 첫 100 s 는 나빠지지 않았다 (100 s ATE 0.82 → 0.72, 0.47 → 0.48 cm). 사전 규칙의 권고도 Z2.

  • 왜 되나: 지금 설정(chi² 배수 0)은 ZUPT 가 영상 시차만 본다. 손이 화면에 들어오면 시차 검사가 떨어지고 그 순간 갱신할 특징도 0 이라 IMU 만 적분했다. chi² 배수를 1 로 하면 시차가 떨어져도 IMU 가 정지라고 하면 (자이로·가속도 잔차가 정지 모델에 맞고 속도 < 0.1 m/s) 정지 갱신을 한다. Z2 에서 이런 'IMU 만으로 정지' 갱신은 실행마다 130–182 번, 모두 100 s 뒤 (내려놓은 뒤) 에만 일어났고 손에 든 움직임 중(≤ 100 s)에는 0 번.
  • Z1 (chi² 배수 1 만) 도 도움(224323 1.3 cm)이지만 잡음 배수 10 이라 IMU 판정이 느슨해 움직이는 중에도 13–21 번 정지로 받았다 → 223815 한 실행이 마지막 창 0.6 → 3.5 cm. 그래서 Z2 가 낫다.
  • Z3 (OpenVINS 기본 chi² 배수 5) 는 움직임 중 101–150 번 잘못 정지 → 첫 100 s ATE 0.5 → 4.2 cm, 223815 한 실행 축척 0.60. 쓰면 안 됨.
  • H (바깥 IMU 정지 검출 → 프레임 붙잡기) 도 통과 (224323 1.26 cm, 끝 정지 이동 0.62 cm, 첫 100 s 오히려 0.82 → 0.47 cm). 다만 VIO 가 내는 속도는 정지 중에도 약 5 cm/s 로 남는다 (ZUPT 는 속도를 0 으로 만들지 않고 상태를 멈춰 둠 → 다시 움직이면 그 속도로 시작, 추정 위험). Z2 는 이 값이 1 cm/s. 브리지 입력을 바꿔야 해서 Z2 보다 손이 많이 감.
  • 감시 (막지 않고 알림): 특징 게이트 F5 (ZUPT 실패 + 갱신 특징 0 이 5 프레임) 는 기준에서 내려놓은 직후 115–117 s (오차 0.4–1.0 cm) 와 손이 들어온 133.2–133.3 s 에 울렸다 — 오차가 커지기 전. 하지만 움직이기 시작하는 순간(12.6 s) 헛경보 1 번이 기준·Z2·H 의 모든 실행에 있다 (정지 → 움직임 바뀔 때 잠깐 특징 0; Z1·Z3 는 1–8 번). F30 (0.5 s) 은 224323 기준 3 실행 중 2 개만 133 s 에 울려 늦고 놓침. Z2·H 를 켜면 133 s 뒤 경보가 사라진다 (실제로 괜찮으니 맞는 동작). 충격 표시(|a|−g > 15 m/s² 뒤 3 s 안에 IMU 정지)는 한 번도 안 울림: 정지 판정이 충격 3.1 s (223815)·4.5 s (224323) 뒤에야 시작. 사후로 5 s 로 늘리면 둘 다 잡히고 헛표시 0 (사후 변경, 확정 아님).
  • 다음 할 일 (제안): ① Z2 를 앱 설정(make_ov_config / config/mono)에 넣기 전에 다른 녹화(c5 짧은 정지 5 개, 밤샘 녹화)로 초기화·무너짐 회귀 확인 ② 실제 드론 착지 녹화 (진동·프롭 바람에서 IMU 판정이 정지를 놓칠 수 있음) ③ F5 는 '정지에서 움직임으로 바뀐 뒤 1 s' 는 쉬게 하는 규칙을 사전 등록 후 시험.
