# C5 시험 계획 (사전 등록, 2026-10-20) — "붕괴의 주원인 = 느슨한 초기화"

이 파일은 **실행 전에** 커밋한다 (커밋 시각 = 등록 시각). 결과를 본 뒤 아래 기준을 바꾸지 않는다.
바꿔야 하면 이 파일 아래 "변경 기록" 에 시각·이유를 적고, 결과 문서에 원래 기준의 판정도 같이 적는다.

## 1. 가설과 판정 규칙
- C5: 벤치의 붕괴(collapse)는 주로 느슨한 초기화 설정(낡은 템플릿: 정지 판정 시차 15 px, init_imu_thresh 1.0 m/s²,
  init_dyn_use true) 때문이다.
- 대조: 같은 벤치 버전에서 초기화 값만 `make_ov_config.py` (실제 앱 경로) 의 엄격한 값으로 바꾼다.
- **판정 (토론 docs/critic_debate_20261020.html 4절 2번)**: 이전에 붕괴한 녹화 7 개 중 **5 개 이상**에서 설정 (a) 의
  붕괴가 사라지면 C5 유지(“주원인 후보” 로 다시 올림). 아니면 **C5 철회**.
- 판정은 설정 (a) 하나로만 한다. (b)·(d) 는 보조 정보 (여러 설정 중 좋은 것을 고르는 일을 막기 위해).

## 3. 실행 조건 (모든 설정 공통)
- 벤치 `imu_learn/vio_bench_hs.py` 한 버전 (결과마다 git 해시·파일 blob 기록), 진단 브리지 `tools/ov_bridge_diag`
  (추정값은 공유 브리지와 같음, collapse_run.py 주석). 학습 보정 끔 (parts=raw, Android 1/4 IMU 그대로 — 이 녹화엔 16/35 없음).
- --noise meas ×10, 60 fps, 640x360, 60 s, 시작 지연 0 / 1 / 2 s (같은 녹화의 다른 초기화 3 번).
- 동시 실행 4 개 이하.
- 설정:
  - **(a) strict** = make_ov_config.py `--init static` 의 초기화 값 (init_window_time 1.5, init_imu_thresh 0.3,
    init_max_disparity = f·tan 0.3° ≈ 2.2 px @ f 428, init_dyn_use false). 값은 make_ov_config 함수에서 가져온다 (복사 안 함).
  - **(b) strict + 긴 clone 창** = (a) + max_clones 30 (60 fps 에서 0.5 s; 기본 11 = 0.18 s).
    대비책: 10 s 조각 시간 측정에서 30 이 11 보다 프레임당 3 배 넘게 느리면 22 로 (측정 전 결정).
  - **(c) loose** = 예전 템플릿 그대로 (15 px, 1.0 m/s², init_dyn_use true) — 같은 벤치 버전에서 다시 돌린 공정한 기준.
  - (d) strict-dyn (보조, 시간 남으면) = make_ov_config.py `--init dynamic` 값 (창 1.0 s, 0.5 m/s², 0.3°, init_dyn_use true).

## 4. 실행 하나의 이름표
- **초기화 성공**: 클립 안에서 OpenVINS 가 tracking 상태가 됨. 기록: 초기화 방식(정지/동적, DEBUG 로그),
  클립 시작부터 초기화까지 시간(s), 초기 자이로 바이어스 |bg|(°/s), 초기화 뒤 남은 클립 비율(%).
- **붕괴** (runs/collapse 와 같은 정의, collapse_signals.label): 초기화 뒤 10 s 창에서 Sim3 스케일 < 0.5 또는 > 2,
  또는 SE3 ATE > 10 cm. 창이 10 s 보다 짧으면 5 s 창 값. 정답 매칭이 부족하면 "이름표 없음".
- 초기화 안 됨 / 이름표 없음 은 붕괴도 정상도 아님 (따로 셈).

## 5. 녹화 하나의 판정 (설정마다)
- **붕괴 사라짐**: 이름표가 붙은 실행(= 초기화 성공 + 이름표 있음)이 3 개 중 **2 개 이상**이고, 그중 붕괴가 **0 개**.
- **시험 안 됨**: 이름표 붙은 실행이 2 개 미만 (엄격한 설정에서 초기화를 못 함). → **사라짐으로 세지 않는다**
  (C5 를 올리려면 초기화가 되고 정상이어야 한다). 보고서에는 따로 개수를 적는다.
- 그 밖 = 붕괴 남음.

## 6. 주 지표와 보조 지표
- 주 지표: 이전 붕괴 7 개 중 (a) 에서 "붕괴 사라짐" 인 녹화 수 → 1절 규칙.
- 보조 (설정별·녹화별): 붕괴 실행 수 / 이름표 실행 수, 초기화 성공률, 초기화까지 시간, 덮은 클립 비율, 초기화 방식,
  초기 |bg| (|bg| > 0.5 °/s 인 초기화 수 = 토론의 "바이어스 게이트" 가 거부했을 수), 10 s 창 스케일·ATE,
  초기화 뒤 전체 ATE·스케일·RPE 1 s, 프레임당 시간.
- 공정성 확인: (c) 에서 7 개가 실제로 붕괴하는지 같이 적는다. (c) 에서 붕괴가 하나도 없는 녹화는 "기준 붕괴 재현 안 됨"
  으로 표시하고, (c) 로 확인된 녹화만으로 센 값도 보조로 적는다 (판정은 1절 그대로).

## 7. 한계 (미리 적어 둠)
- 손에 든 녹화이고 2 s 정지로 시작하는 녹화가 0 개 (docs/collapse_verify.md) → (a) 는 초기화가 늦거나 안 될 수 있다.
  이것은 C5 의 시험 조건으로는 불리하지만, 실제 앱 설정을 그대로 시험하는 것이다.
- 시작 위치 3 개 (토론은 5 개 이상을 권함) — 시간 제약. 동적 초기화는 벽시계 한도가 있어 CPU 부하로 결과가 흔들릴 수 있다.
- 독립 단위는 녹화 (11 개). 같은 녹화 실행은 독립 아님.
