## 2. H 의 ① 어김은 진짜인가
- 같은 입력 반복 차이 = 0 (결정성) → "반복 잡음" 때문은 아님. 어김은 규칙상 진짜.
- 그러나 크기는 시작 위치 민감도와 같은 수준: base 자체가 ±0.25 s 시작 차이로 묶음 안 0.1–0.8 cm 흔들림 (T_221052_S1 0.52–1.00, T_224323_S1 0.93–1.76).
  Z2 도 T 묶음 여러 곳에서 짝 단위 한도를 넘었다 (T_221052_S1 dp025 +0.72 등) — 중앙값만 통과.
- 묶음별:
  - T_214138_S2: 한도 1.05 를 0.02 cm 넘음. 단 3 짝 모두 나빠짐 → 작지만 일관.
  - T_222747_S1: d0 +0.53, dm025 +0.52, dp025 −0.05 → 2/3 일관.
  - T_224323_S1: 중앙 1.47 은 dp025 값인데 그 짝은 base 1.76 보다 **좋아짐**; 어김은 dm025 한 짝 3.90 (+2.90) 이 중앙을 끌어올린 것 → 이상치 하나에 기댐.
  - F_222747: base 도 3/3 무너진 녹화. 무너짐끼리 비교 (H 239/270/204 vs base 156/121/6842) — o2 는 H 가 훨씬 덜 나쁨. 의미 약함.
  - O_154320 o2 2.71→6.99 (축척 0.846): 진짜 짝 단위 악화. 같은 묶음에서 Z2 도 o1 3.00→7.22 를 보였음 → 이 녹화가 시작 위치에 민감.
- 결론: "4 묶음 어김" 은 사전 규칙상 맞지만, 실질 신호는 T_214138_S2·T_222747_S1 (작음, 0.3–0.5 cm) 과 단일 짝 2 개 (T_224323_S1 dm025, O_154320 o2).
  "H 가 ATE 를 체계적으로 나쁘게 한다" 는 근거는 약하고, "규칙 통과 못 함 → 앱 설정 보류" 는 맞다.
