# i3 확인 시험 — 사전 등록 (2026-10-21 22:00, 새 녹화를 찍기 전에 커밋)

목적: still-hold `1.5:0.05:0.05` + 초기화 3 s 뒤 켜기 (i3, docs/h_arm_init.html) 를 앱 설정에 넣어도 되는지,
**아직 아무도 본 적 없는 새 녹화** (2026-10-21 밤 이후 촬영, 내려놓기 장면 포함) 로 판정한다.

## 데이터
- 새 녹화 전부 (앱 v0.5 이상, 원본 IMU 16/35). 보드 모드(회사 모니터 / 노트북 잘림 42.86 mm / 노트북 맞춤 32.0 mm 또는 카드 보정값) 는 녹화마다 기록.
- 정답: imu_gt_rs + spline_gt knot 0.0125 (카메라만). 정답 품질이 나쁜 녹화(자세 OK < 50 %)는 결과를 보기 전에 뺀다.

## 비교
- base (still-hold 끔) vs i3. 같은 코드·설정·스레드, 시작 위치 3 개 (정지 시작 안). 원본 IMU, 정적 초기화 창 1.0 s / 15 px / 동적 끔.

## 판정 기준 (바꾸지 않음)
1. ATE: 녹화별 중앙값 전체 ATE 가 base 대비 ≤ 10 % 또는 ≤ 0.2 cm 나빠짐. 짝별 최악도 함께 보고.
2. 새 무너짐 0 (무너짐 = 초기화 뒤 10 s 창 Sim3 축척 0.5–2 밖 또는 그 창 ATE > 10 cm, 또는 전체 축척 0.5–2 밖 / 전체 ATE > 10 cm).
3. 붙잡은 구간의 정답 속도 (3'): **정답 품질 문** — 표본과 ±0.1 s 이웃 모두 보이는 코너 ≥ 12 — 을 통과한 표본만 센다.
   > 2 cm/s 비율 ≤ 0.5 % 그리고 최대 ≤ 3 cm/s. 문을 통과한 표본이 0 개인 붙잡은 구간은 "시험 안 됨" (통과 아님).
   (이 문은 docs/gt_speed_noise.html 에서 결과를 보고 고른 값이라, 그 녹화가 아닌 **새 녹화에서만** 판정에 쓴다.)
4. 내려놓기 개선: 내려놓은 뒤 정지 구간의 VIO 이동 (정답이 있는 창) 이 base 보다 작아야 함 — 녹화 단위 부호 집계, 녹화 수가 적으면 "근거 약함".

## 결론 규칙
- 1·2·3 모두 통과 + 4 가 개선 쪽 → "앱 설정에 넣어도 됨 (추정, 녹화 N 개)". 하나라도 실패 → 넣지 않음, 실패 원인 보고.
- 검증 담당이 결과를 반박 시도한 뒤 확정.

## 추가 (2026-10-21 21:50, 결과를 보기 전 — 사용자 알림: 가이드의 정지 구간에 완벽히 멈추지 못했을 수 있음)
- 정지 구간은 가이드 시각표(0–10, 55–70, 120–150 s)가 아니라 **IMU 로 판정**한다: 0.5 s 창 자이로 표준편차 < 0.01 rad/s 그리고 평균 |ω| < 0.03 rad/s 가 1.5 s 이상 이어진 구간 (docs/endstill_check.html 와 같은 방식).
- 가이드 시각표는 "어디쯤에서 찾을지" 참고로만 쓴다. IMU 정지가 없는 내려놓기 단계는 기준 4 에서 "시험 안 됨" 으로 센다 (통과 아님).
- 정지 시작이 1.5 s 미만인 녹화는 정적 초기화 시험(기준 1–3 의 시작 위치)에서 빼고 그 사실을 보고한다.
