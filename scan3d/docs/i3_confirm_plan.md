# i3 확인 시험 — 사전 등록 (2026-10-21 22:00, 새 녹화를 찍기 전에 커밋)

목적: still-hold `1.5:0.05:0.05` + 초기화 3 s 뒤 켜기 (i3, docs/h_arm_init.html) 를 앱 설정에 넣어도 되는지,
**아직 아무도 본 적 없는 새 녹화** (2026-10-21 밤 이후 촬영, 내려놓기 장면 포함) 로 판정한다.

## 데이터
- 새 녹화 전부 (앱 v0.5 이상, 원본 IMU 16/35). 보드 모드(회사 모니터 / 노트북 잘림 42.86 mm / 노트북 맞춤 32.0 mm 또는 카드 보정값) 는 녹화마다 기록.
- 정답: imu_gt_rs + spline_gt knot 0.0125 (카메라만). 정답 품질이 나쁜 녹화(자세 OK < 50 %)는 결과를 보기 전에 뺀다.

## 비교
- base (still-hold 끔) vs i3. 같은 코드·설정·스레드, 시작 위치 3 개 (정지 시작 안). 원본 IMU, 정적 초기화 창 1.0 s / 15 px / 동적 끔.

## 판정 기준 (바꾸지 않음)
1. ATE: 녹화별 중앙값 전체 ATE 가 base 대비 ≤ 10 % 또는 ≤ 0.2 cm 나빠짐. 짝별 최악도 함께 보고.
2. 새 무너짐 0 (무너짐 = 초기화 뒤 10 s 창 Sim3 축척 0.5–2 밖 또는 그 창 ATE > 10 cm, 또는 전체 축척 0.5–2 밖 / 전체 ATE > 10 cm).
3. 붙잡은 구간의 정답 속도 (3'): **정답 품질 문** — 표본과 ±0.1 s 이웃 모두 보이는 코너 ≥ 12 — 을 통과한 표본만 센다.
   > 2 cm/s 비율 ≤ 0.5 % 그리고 최대 ≤ 3 cm/s. 문을 통과한 표본이 0 개인 붙잡은 구간은 "시험 안 됨" (통과 아님).
   (이 문은 docs/gt_speed_noise.html 에서 결과를 보고 고른 값이라, 그 녹화가 아닌 **새 녹화에서만** 판정에 쓴다.)
4. 내려놓기 개선: 내려놓은 뒤 정지 구간의 VIO 이동 (정답이 있는 창) 이 base 보다 작아야 함 — 녹화 단위 부호 집계, 녹화 수가 적으면 "근거 약함".

## 결론 규칙
- 1·2·3 모두 통과 + 4 가 개선 쪽 → "앱 설정에 넣어도 됨 (추정, 녹화 N 개)". 하나라도 실패 → 넣지 않음, 실패 원인 보고.
- 검증 담당이 결과를 반박 시도한 뒤 확정.

## 추가 (2026-10-21 21:50, 결과를 보기 전 — 사용자 알림: 가이드의 정지 구간에 완벽히 멈추지 못했을 수 있음)
- 정지 구간은 가이드 시각표(0–10, 55–70, 120–150 s)가 아니라 **IMU 로 판정**한다: 0.5 s 창 자이로 표준편차 < 0.01 rad/s 그리고 평균 |ω| < 0.03 rad/s 가 1.5 s 이상 이어진 구간 (docs/endstill_check.html 와 같은 방식).
- 가이드 시각표는 "어디쯤에서 찾을지" 참고로만 쓴다. IMU 정지가 없는 내려놓기 단계는 기준 4 에서 "시험 안 됨" 으로 센다 (통과 아님).
- 정지 시작이 1.5 s 미만인 녹화는 정적 초기화 시험(기준 1–3 의 시작 위치)에서 빼고 그 사실을 보고한다.

## 추가 2 (2026-10-21 22:15, 실행 담당 — 새 녹화의 VIO·정답 결과를 하나도 보기 전. 계획에 안 적힌 세부만 정함, 기준 1–4 숫자는 그대로)
- **보드**: 녹화마다 cam5.mp4 의 마커 번호로 자동 선택 (imu_learn/board_pick.py, 40 장 표본): 0–21 → board_laptop_6x6.json (42.86 mm),
  100–121 → board_laptop_fit_6x6.json (32.03 mm). 두 범위가 섞이면(작은 쪽 > 5 %) 정답을 만들지 않고 보고. IMU 축척 검사(scale_ls,
  spline 정답)가 |s − 1| > 0.15 이면 "보드?" 로 표시하고 입력 점검 문서(docs/overnight2_input_audit.md)와 대조한다.
- **정답 품질로 빼기** (계획 "자세 OK < 50 %"): imu_gt_rs 의 프레임별 ok 비율 (ok 그리고 |p| < 1.2 m) / 전체 프레임 < 0.5 이면 VIO 실행 전에 뺀다.
- **정지 판정** (추가 1 그대로): 원본 자이로 type 16, 0.5 s 창 0.1 s 간격, 축별 std < 0.01 rad/s 그리고 |평균| < 0.03 rad/s 인 창이
  이어진 구간 = [첫 창 시작, 마지막 창 시작 + 0.5 s], 길이 ≥ 1.5 s 만 정지. 시간은 IMU 시계.
  - 시작 정지 = 첫 프레임(IMU 시계로 바꾼 시각) 뒤 10 s 안에서 시작하는 첫 정지 구간. L = 그 구간 중 첫 프레임 이후 부분의 길이.
  - 내려놓은 뒤 정지 = 가이드 참고 창 [50, 75] s 와 [115, 끝] s (첫 프레임 기준) 에 겹치는 정지 구간 중 가장 긴 것 (창마다 하나).
- **시작 위치 3 개**: 시작 정지 안에서 o_k = max(0, 정지 시작 − 첫 프레임) + k·Δ, k = 0,1,2, Δ = min(1.0, (L − 1.0)/2) s
  (마지막 시작 뒤에도 정지가 ≥ 1.0 s = 초기화 창 남음). L < 1.5 s 면 그 녹화는 VIO 실행에서 빼고 보고 (기준 4 도 "시험 안 됨").
- **실행 설정** (base·i3 같음, 지난밤 F_ 묶음과 같은 벤치 인자): c5_run 경로 (z2_isolate.py job), --init-cfg strict --init-window 1.0
  --init-disp 15 --clones 11 --noise cfg --imu-lead 2.0 --max-secs 0 (끝까지) --decode-threads 2 --imu-raw, OpenVINS
  num_opencv_threads=2, 동시 ≤ 5. i3 = --still-hold 1.5:0.05:0.05:i3. 다른 설정의 실행을 복사해 쓰지 않음 (24 실행 전부 새로).
- **기준 1**: ATE = 벤치 ate_cm (초기화 뒤 전체, SE3, 정답 imu_gt_spl). 녹화별 3 시작 중앙값, 한계 max(base×1.10, base+0.2).
  초기화 못 한 실행은 중앙값에서 빠지고 기준 2 에서 센다.
- **기준 2**: 무너짐 = c5_overnight_analyse.analyse_run 의 10 s 창 (축척 0.5–2 밖 또는 ATE > 10 cm) 또는 벤치 전체 축척 0.5–2 밖
  또는 전체 ATE > 10 cm. "새 무너짐" = 같은 녹화·같은 시작에서 base 는 정상인데 i3 는 무너짐·초기화 실패·점수 없음.
- **기준 3 (3')**: 붙잡은 구간 = 실행 JSON 의 hold_segments_imu_ns (끝 없음 = 마지막 포즈). 정답 속도 = imu_gt_spl ±0.1 s 중앙 차분
  (z2_regress.gt_speed 와 같음, 이웃 ±0.02 s 안). 문 = 표본·두 이웃 모두 n_corners ≥ 12. 녹화별로 3 시작의 모든 붙잡은 구간 표본을
  모아 > 2 cm/s 비율 ≤ 0.5 % 그리고 최대 ≤ 3 cm/s. 문 통과 표본 0 개인 붙잡은 구간은 하나하나 "시험 안 됨" 으로 적고,
  그런 구간이 하나라도 있으면 그 녹화의 기준 3 은 "통과" 가 아니라 "일부 시험 안 됨" (계획 문구대로: 통과 아님).
- **기준 4**: 내려놓은 뒤 정지 구간마다 양 끝 0.5 s 잘라낸 창에서, 정답 표본(ok)이 ≥ 5 개 있고 그 창에 추적 포즈가 있는 경우만
  ("정답이 있는 창"). VIO 이동 = 그 창의 첫·마지막 추적 포즈 위치 차이 |ΔP| (cm, VIO 좌표 그대로). 창마다 3 시작 중앙값,
  녹화 값 = 시험된 창들의 합 (base·i3 모두 값이 있는 창만). i3 < base → 개선(+), > → 나빠짐(−), 차이 0.05 cm 안 → 같음.
  녹화 부호 집계에서 + 가 − 보다 많으면 "개선 쪽". 시험된 녹화 < 3 이면 "근거 약함" 표시. 시험된 창이 하나도 없으면 기준 4 "시험 안 됨" (개선 아님).
