## 2부 가속도 행렬 A 의 방향

**적용 방식 비교 (전부 같은 방향)**
- 학습 `imu_learn/train_imu.py:227-229` `a = X @ A.T + ba` = A·a_meas + ba; 적분 `:281` `a_w = R·acc + gb` (gb = 크기 9.80665 로 고정한 중력, `:387-393`). 즉 A 는 "측정 → 참 비력" 보정 행렬.
- 벤치 `imu_learn/vio_bench_hs.py:189-192` (지금 줄 번호; 예전 184-186) `a_i @ A.T + ba` — 학습과 같은 식.
- 데이터 맞춤 `imu_learn/calib_apply_test.py` `lsq(a_m, f_gt)` → `f_gt ≈ M·a_m + b` — 같은 방향 (M 은 A 를 추정).

**합성 시험** (`accel_matrix_direction.py`, 120 s, 500 Hz, 넓은 자세 변화, 센서 a_meas = S·f + b + 잡음, |S−S⁻¹| 82e-3 로 실제보다 10 배 크게)
- train_imu.Calib + train_imu.window_loss 로 학습: dist(A_fit, S⁻¹) **1.5e-3**, dist(A_fit, S) 80.5e-3 → **학습은 올바른 보정 S⁻¹ 을 찾는다**.
- 벤치 식과 Calib.forward 차이 최대 1.8e-6 m/s² (같은 식).
- 참 비력 대비 RMS: 벤치 방식 2.0 mg, 거꾸로 (A⁻¹(x−ba)) 41.7 mg, 보정 없음 20.8 mg.
- calib_apply_test 의 LSQ (중력 크기 자유로 번갈아 맞춤) 를 같은 합성 자료에: dist(M, S⁻¹) **28.7e-3** (방향은 맞게 S⁻¹ 쪽), 중력 크기를 10.03 으로 잘못 잡음 (2.3 % 축척이 M 으로 샘). 즉 **이 LSQ 자체 오차가 약 30e-3**.

**실제 접힘 (fold) 의 크기** (on_spl_*, on_mid_s0_*)
- |A−I|_F = 7.0~9.4e-3. 1 g 에 A 를 쓰나 안 쓰나 차이: 중앙 3.6~4.8 mg, 최대 6.9~9.4 mg. **A 와 A⁻¹ 의 차이: 중앙 7~10 mg, 최대 14~19 mg**. ba 는 약 0.02~0.03 m/s² (2~3 mg).
- 실제 자료 LSQ 행렬의 단위행렬 거리: 9 (161035), 29 (131326), 67 (154320), **1115** (145816, M_zz = 2.05 — 맞춤 실패) e-3. 합성에서 본 LSQ 오차 (~29e-3) 와 같거나 크다. 이 잡음 속에서 dist(M,A) 와 dist(M,A⁻¹) 의 차이 (4~9e-3) 는 의미 없다. 161035 는 I 가 가장 가깝다 (9.1 < A⁻¹ 11.3 < A 14.8).
- 같은 자료의 RMS 잔차는 4 개 중 3 개 (131326, 154320, 161035) 에서 벤치 방식 < 거꾸로 방식 (예: 131326 364.4 vs 367.0 mm/s²); 145816 만 반대 (LSQ 가 망가진 녹화).

**판정**: A 는 학습·벤치·시험 어디에서도 거꾸로 쓰이지 않는다 (맞음). 이전 검증의 "A⁻¹ 이 4/4 더 가깝다" 는 LSQ 기준이 A 의 크기보다 훨씬 거칠어서 생긴 결과 → 방향 판단 근거로 **부적합**. 다만 학습된 A 의 비대각·축척 (≈8e-3, 효과 4~9 mg) 이 실제 센서 오차를 반영하는지 (학습이 다른 오차를 A 로 흡수했는지) 는 이 자료로 **불확실** — 손 녹화 1 s 창에서는 수 mg 수준의 A 가 잘 보이지 않는다 (합성처럼 6 면 정지 자세 자료가 필요, IMU_PLAN.md:19).
