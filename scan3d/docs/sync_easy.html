카메라 사진과 IMU 값은 어떻게 짝지어지나

카메라는 1초에 240장(또는 60장), IMU는 1초에 500번 값을 냅니다. 둘을 같은 시각, 같은 방향으로 맞춰야 "이 사진이 찍힐 때 IMU는 이 값이었다"를 알 수 있습니다. 4단계로 맞춥니다.

한 줄 요약
  1. 같은 시계로 바꾸기 — 영상 파일 시각을 IMU와 같은 폰 시계로 옮김
  2. 사진 한 장의 정확한 순간 정하기 — 노출 가운데 + 보드가 찍힌 줄
  3. 남은 작은 시간차(dt) 찾기 — 자이로가 본 회전 vs 보드가 본 회전을 겹쳐 봄
  4. 축 방향(R) 맞추기 — IMU 칩과 카메라가 살짝 틀어진 각도

1같은 시계로 바꾸기

폰 안에는 시계가 두 개 있습니다.

  • 부팅 시계(BOOTTIME): 폰이 잠들어 있던 시간도 셉니다. IMU 값과 카메라 사진 정보가 이 시계를 씁니다.
  • 깨어 있는 시계(MONOTONIC): 잠든 시간은 빼고 셉니다. 240 fps 영상 파일(mp4)의 시각이 이 시계입니다.

그다음, 카메라가 사진마다 따로 알려 주는 정확한 센서 시각 목록에서 2 ms 안쪽으로 가장 가까운 것을 찾아 짝짓습니다(사진 간격이 4.2 ms라 헷갈릴 일이 없습니다). 짝을 못 찾은 사진은 바로 앞 사진의 차이를 그대로 씁니다.

사진 시각 = 영상 시각 + clock_offset → 2 ms 안의 센서 시각으로 바꿈

60 fps 모드는 사진마다 센서 시각이 바로 오므로 이 단계가 필요 없습니다.

2사진 한 장의 "찍힌 순간" 정하기

사진은 한순간에 찍히지 않습니다. 셔터가 열려 있는 시간(노출)이 있고, 위 줄부터 아래 줄까지 차례로 읽힙니다(롤링 셔터).

그래서 "사진 시각" = 노출 가운데, 거기에 보드가 사진의 위쪽에 있으면 조금 빠르게, 아래쪽에 있으면 조금 늦게 고칩니다.

t = t_가운데 + (보드 모서리 평균 y / 사진 높이 − 0.5) × skew

예: 60 fps에서 초당 2 rad로 돌리면 고치지 않을 때 위·아래 끝에서 약 0.5° 어긋납니다. 240 fps는 skew가 1/3이라 이 오차도 1/3.

3남은 작은 시간차(dt) 찾기

1·2단계를 해도 카메라 처리 지연 때문에 몇 ms 어긋남이 남습니다. 이건 직접 잴 수 없어서, 같은 회전을 두 센서가 어떻게 봤는지 겹쳐 보고 찾습니다.

  • 자이로: "폰이 이만큼 돌았다"를 직접 잼
  • 보드 사진: 사진마다 보드에 대한 폰 자세를 계산 → 사진끼리 차이 = 돌아간 양
방법무엇을 겹치나찾는 범위평가
처음 방법회전 빠르기(크기만)±150 ms, 1 ms 간격대충 위치 찾기용. ±2 ms 틀려도 차이가 1%뿐이라 정밀하지 않음
정밀 방법0.2초 동안 돌아간 양(방향까지)±15 ms, 0.2 ms 간격dt와 축 방향(4단계)을 같이 맞춤. 지금 이 값을 씀
IMU 시각 + dt = 카메라 시각 (지금 녹화들: dt = −4.6 ~ +1.6 ms)

4축 방향(R) 맞추기

IMU 칩과 카메라는 폰 안에서 완전히 같은 방향이 아닙니다. 그래서 자이로의 "x축으로 돌았다"가 카메라에서는 살짝 다른 축입니다. 3단계에서 회전을 겹칠 때 이 틀어진 각도(R)도 같이 구합니다.

확인결과
녹화마다 따로 구한 R끼리1.3° 안에서 같음 → 매번 같은 값이 나옴
폰 공장 기본값과 비교0.9 ~ 1.8° 다름 → 공장값보다 우리가 잰 값을 씀

카메라와 IMU의 위치 차이(몇 cm)도 있는데, 이건 학습의 "물리 보정" 단계에서 같이 구합니다.

맞춘 뒤: 사진 사이의 IMU는 어떻게 쓰나

IMU 값을 차례로 더해서(적분) 다음 사진 때 폰이 어디 있을지 예측하고, 보드 사진이 알려 주는 정답과 비교합니다. 그 차이를 줄이도록 보정(+CNN)을 학습합니다. 240 fps면 사진 사이 IMU 값이 약 2개라 정답이 아주 촘촘합니다.
