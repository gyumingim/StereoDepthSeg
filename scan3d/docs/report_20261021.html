3. 어제 믿던 것과 달라진 점

  • 어제: "느슨한 초기화(loose)가 무너짐의 주원인일 것"(C5) → 오늘: 정지 시작 녹화로는 시험 자체가 갈리지 않음. 정지 없는 221925 하나에서만 차이가 보임. 원인은 열린 질문.
  • 어제: 노트북 화면 칸 크기 40.70 mm(IMU 7.5 s 추정) → 오늘: 녹화 6개로 44.49 mm 추정. 정답 위치가 약 9% 작게 만들어져 있음.
  • 어제: IMU 보정·바이어스 보정이 VIO를 도울 수 있다 → 오늘: 녹화 5개에서 구별되는 이득 없음.
  • 새로 안 것: 시작 시점 0/1/2 s 반복은 무작위 반복이 아니라 시작 시점 민감도임(실행은 결정적).

4. 드러난 문제와 정정

  • 성공 판정 구멍: "성공"을 초기화 뒤 첫 10 s만 보고 정해서, 나중에 수 m로 발산한 Allan 실행 6개를 성공으로 셈. A·B·C 주 결론에는 영향 없음(5 cm 넘는 성공 실행 없음). 오늘 전 구간 기준을 더함.
  • 빠진 계획 항목: 계획 5절의 "새 녹화로 학습한 물리 보정"과 "바이어스+온도 1차식"은 사전 규칙에서 빠져 실행되지 않았는데, 결과 HTML은 "계획대로"라고 씀 → 정정 필요.
  • "확정"이라는 말 과장: 녹화 5개라 부호 검정 최소 p가 0.0625. 어떤 결과도 확정이 될 수 없음.
  • 기록 시각: 사전 규칙 문서의 변경 기록 시각 몇 개가 실제 커밋보다 늦게 적힘. 내용 문제는 아님.
  • 앱 버그: 녹화 3/8에서 IMU 파일 한 줄이 잘리고 176~288 ms 빈틈. 이번엔 분석 구간 밖이지만 앱에서 고칠 거리.
