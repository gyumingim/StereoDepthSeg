## 실험 1. 짧은 정지에서 정적 전용 초기화의 창·시차 문턱

### 질문
드론이 이륙 전에 약 1–2 s 만 서 있을 때, 정적 전용 초기화(동적 끔)의 창 길이 W 와 시차 문턱 D 를 어떻게 두면
**무너짐 0** 이면서 그 정지 안에 초기화가 되나? "초기화 안 됨"은 이륙 전에 알 수 있는 안전한 실패, "무너짐"은 비행 중 실패.

### 입력 (고정)
- 녹화 5개 (처음 정지 있음): hs_20261020_214138, 221052, 222747, 223815, 224323.
- 자르기: c5 재시험과 같음 — 첫 VIO 프레임 = 클립 시작 + motion_start_s − S + δ (`runs/overnight_vio/inputs/<rec>_still.json`),
  S ∈ {1, 2} s, δ ∈ {−0.25, 0, +0.25} s (반복 3 회).
- IMU 앞당김: 0 s (주) 와 2 s (보조, 같은 행렬).
- 설정: strict 기반 정적 전용 (init_dyn_use false, init_imu_thresh 0.3) 에서 두 값만 바꿈:
  init_window_time W ∈ {0.5, 1.0, 1.5} s, init_max_disparity D ∈ {2.24, 5, 15} px (640x360, f ≈ 428 → 2.24 px = 0.3°, 앱 기본).
  벤치에 `--init-window`, `--init-disp` 덮어쓰기를 추가 (주지 않으면 기존 동작 그대로).
- 그 밖: IMU 원본 16/35, 잡음 cfg, clones 11, 60 fps, 640x360, 클립 20 s, 디코드 4 스레드 (부하만, 프레임 같음), nice 5, 동시 OpenVINS ≤ 3.
- 행렬: 2 앞당김 × 2 S × 3 W × 3 D × 5 녹화 × 3 δ = **540 실행**. 순서: L0 먼저 (S2 → S1), 다음 L2.
- 코드: imu_learn/vio_bench_hs.py, c5_run.py, c5_initwin.py (일정), c5_initwin_analyse.py (분석). 실행마다 JSON 에 bench/runner blob,
  바이너리 sha256, 실제 yaml, DEBUG 로그(gz) 저장. 버전이 섞이면 판정 무효.

### 미리 알아 둔 것 (시간 재기 실행 1 개에서, 판정 정의에 반영)
- 벤치 결과의 `t_init_clip_s` (첫 'tracking' 포즈) 는 **초기화 시각이 아니다**: 브리지는 OpenVINS 의 첫 영상 갱신 뒤에야
  tracking 을 낸다 (VioManager::initialized() = is_initialized_vio && timelastupdate != −1). 정적 초기화 뒤에는 ZUPT 가 정지 동안
  갱신을 막으므로 tracking 은 움직임 시작 무렵에 나온다. → 이번 분석은 **DEBUG 로그의 "successful initialization" 바로 앞 [DIAGT] 시각**을
  초기화 시각으로 쓰고, 포즈 줄의 브리지 시각 `t` 로 클립 시각으로 바꾼다. (c5 재시험의 "늦은 초기화" 집계도 이 정의 차이가 있음 → 결과 문서에 표시.)
- OpenVINS 는 첫 정적 판정을 브리지 시각 W + 0.1 s 뒤에야 한다 (oldest_time ≥ 0, 브리지 시각 0 = 첫 메시지). 앞당김 0 이면 첫 프레임 + W + 0.1 s.

### 실행 단위 판정
- 움직임 시작 = c5 재시험의 0.1 s 창 재측정값 (fine_s: 214138 18.56, 221052 18.34, 222747 11.08, 223815 10.78, 224323 10.32 s, 클립 시작 기준).
  남은 정지 = fine_s − start_off.
- **초기화 안 됨 (안전)**: 클립 20 s 안에 초기화 없음.
- **늦음 (안전, 이륙 전 준비 안 됨)**: 초기화 시각 > 남은 정지 + 0.1 s. (드론은 초기화 전에는 이륙하지 않는다는 전제.) 늦은 실행의 궤적 판정은 참고로만 적음.
- 이륙 전 초기화된 실행: 초기화 뒤 전체 (클립 끝까지) Sim3 축척 0.5–2 이고 SE3 ATE ≤ 10 cm → **성공**, 아니면 **무너짐**.
  맞춘 포즈가 모자라 판정을 못 내면 **미판정 → 무너짐으로 셈** (c5_overnight_analyse.analyse_run 의 전 구간 기준 그대로). 10 s 창 기준은 참고 표시.
- 초기화 바이어스 오차: |bg_init − bg_meas| (mdeg/s, 3 축 노름). bg_init = DEBUG 로그 값 (4 자리, rad/s),
  bg_meas = 그 녹화 처음 정지의 원본 자이로(유형 16 v0..2) 평균, 구간 [클립 시작 + 0.5 s, fine_s − 0.3 s]. 참고: 자이로 1 LSB ≈ 70 mdeg/s.
  (docs/endstill_check.html 의 시작 정지 값과 3 녹화에서 대조해 같은 값인지 확인.)

### 판정 규칙 (결과 보기 전 고정)
- 안전 = 그 설정(W, D)의 **모든 실행 (L0·L2, S1·S2, 60 개) 에서 무너짐 0**.
- 안전한 설정 중 순위: ① L0·S2 성공 수 많음 → ② L0·S1 성공 수 많음 → ③ 이륙 전 초기화 실행의 바이어스 오차 중앙값 작음
  → ④ D 작은 쪽 → ⑤ W 긴 쪽 (보수적). 1 등을 "가장 안전한 정적 전용 설정"으로 쓴다.
- 문구: 녹화 5개·한 장소라 결론은 모두 **추정**. 녹화 단위로도 표시 (무너짐이 한 녹화에 몰렸는지).
- 안전한 설정이 없으면 "무너짐 0 인 설정 없음" 과 무너짐이 가장 적은 설정을 쓴다.
- 미리 적는 예상 (결과로 고치지 않음): W = 1.5 는 S = 1·앞당김 0 에서 대부분 초기화 안 됨/늦음. W = 0.5 는 빨리 되지만 바이어스 평균 구간이
  0.25 s 라 오차가 크고, D = 15 와 겹치면 느린 움직임을 정지로 받아 무너질 수 있음. 221052 (정지 중 화면 시차 5.6–16 px) 는 D = 2.24·5 에서 초기화 안 됨.
