3. **AE 잠금:** 지금은 ae_mode = 1 (자동). 노출 4 ms 고정이지만 ISO 가 놓임마다 96–125 로 달라짐 → ISO·AWB 잠금 또는 값 기록.
4. 조명 고정 (실내등 120 Hz 는 원인 아님 — 바꾸지 말고 기록만), 프레임 빠짐은 지금 수준(5–12 %)이면 됨.
5. 정답 품질: 판 코너 ≥ 12 개가 보이게 (GT 속도 잡음 조건, docs/gt_speed_noise.html).

## 4. 다음 세션 사전 등록 제안 (VIO, 약 2 h)

D (문턱만 올림) 은 1 절에서 버려졌으므로 대신 **G1.0 (자이로 인과 정지일 때만 zupt_max_disparity 1.0, 아니면 0.5)** 를 base · i3 와 비교한다.
구현 = 벤치의 i3 외부 자이로 문을 그대로 쓰고, 프레임 붙잡기 대신 ZUPT 문턱만 바꾸는 진단 빌드 설정 (OpenVINS UpdaterZeroVelocity 에 문턱 setter, 작은 C++ 변경). 실행 전에 base 만으로 초기화·창 실행 가능성 확인 (B′b 교훈).

- 조건: base, i3, G1.0 (문턱 하나만; 0.75 / 1.5 는 하지 않음 — 다중 비교 피함).
- 칸: 214550 B s0 d1/d5/d10 + B′a o0–o2 + L6/L3; 213341 · 213955 · 215348 B s0 d1/d5/d10; 213341 B d1/d5 는 시작 ±0.25 s 로 3 개씩 (판정자 항목 5, 잡음 띠).
  회귀: z2_regress 묶음 전체 (O_131326, F_221052 포함) base vs G1.0.
- 판정 (실행 전에 커밋):
  1. 안전: G1.0 의 실제 stderr 에서 "통과 & 정답 > 2 cm/s & 코너 ≥ 12" 프레임 수 ≤ 같은 칸 base 수 (모든 실행). 새 무너짐 (base 정상 → G 무너짐) 0.
  2. 회귀: z2_regress 묶음 ATE 짝 차이 (G − base) 중앙값 ≤ +0.1 cm, 칸별 최대 악화 ≤ 시작 민감도 띠 (213341 ±0.25 s 실행에서 잰 범위).
  3. 이득: 214550 칸에서 출발 뒤 10 s 연속 ATE 짝 차이 (G − base) 중앙값 < 0, 그리고 base 무너짐 칸 중 G 정상 ≥ 2.
  4. 보고: 규칙 판정과 짝 판정을 나란히. "녹화 ≥ 2" 이득 기준은 214550 만으로는 못 채우므로 결론은 "214550 에서 효과 있음/없음 + 안전" 까지만, 확정은 3 절 새 녹화 뒤.
- 보조 (VIO 동작 불변, 기록만): 진단 빌드가 ZUPT 시차의 평균과 함께 **중앙값** 도 찍게 해 base 를 다시 돌리면, "평균 대신 중앙값" 안 (어두운 띠의 잡음 점에 강함, 추정) 을 같은 1 절 방식으로 헛 통과 검사할 수 있다.
