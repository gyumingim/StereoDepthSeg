# 메타인지 감사 — "지금 로직이 너무 복잡한가?" (2026-10-23, 외부 비판자, 읽기 전용)

## 결론 (먼저)
**네, 너무 복잡하다. 그리고 복잡함이 지금은 답을 늦추고 있다.**
- 검사 사슬(사전 등록 → 검산 → 검증 → 비평 → 재판)은 진짜 실수를 여럿 잡았다. 이건 남긴다.
- 하지만 ZUPT 수정 4 개(A, C, A', A2)가 모두 "불채택" 이 됐다. 그리고 오늘 A/A 시험(base 대 base)에서 기준 2 가 6 번 중 5 번, 기준 3 이 6 번 중 6 번 실패했다 (커밋 634dd5b). **아무것도 안 바꿔도 떨어지는 기준이었다.** 4 번의 판정은 후보가 아니라 자를 잰 것이다.
- 가장 싼 대안인 OpenVINS 기본 옵션 `zupt_only_at_beginning: true` 는 한 번도 돌리지 않았다. 지금까지 stderr 3290 개가 모두 `false` 다. 코드 조사자가 후보 "H" 로 적어 두었지만(runs/zupt_slam_review/code_investigator.md 62 줄) 실행은 없었다.
- **드론 조건 녹화는 0 개다.** recordings/ 92 개 중 모터·진동·비행 녹화가 하나도 없다. 10-22 보고서가 "가장 싸고 먼저" 라고 한 "모터 켠 IMU 기록" 도 아직 안 했다.

## 4. 지금 평가가 드론 질문에 답하나 → 거의 아니다
- 지금 데이터는 손에 든 폰, 화면 속 보드, 내려놓기·들기다. 드론에는 프롭 진동(IMU 포화·롤링 셔터 흔들림), 빠른 회전, 보드 없는 방이 있고, "내려놓은 정지" 대신 호버가 있다.
- 지금 기준은 "정지 처리" 를 다듬는 데 쓰이는데, 드론에서 정지는 이륙 전 몇 초뿐이다.

**"안정적으로 날기" 가 목표라면 다음 3 단계**
1. **모터 켠 진동 녹화** (프롭 없이 → 프롭 달고 묶어 두고). IMU 스펙트럼, 특징 추적 수, 그리고 stock OpenVINS 가 살아남는지 본다. 여기서 막히면 방진 마운트가 먼저다.
2. **stock OpenVINS + `zupt_only_at_beginning=true` 를 기준선으로** 손에 든 비행 흉내(걷기, 호버 흉내, 회전) 5 개에 돌린다. 지표는 3 개: 발산 여부, 이륙 3 s 최대 오차, 1 m 당 표류. 같은 녹화에 VIO 하나(예: VINS-Mono 또는 Basalt)만 더 비교한다.
3. **건강 표시 → 낙하산 판단.** 정확도를 cm 단위로 다듬는 것보다 "무너지는 걸 1 s 안에 알아채는가" 가 비행 안전에 더 직접적이다 (충격 묶음 아이디어를 주 지표로 올린다).

## 5. 단순화 계획
**동결** (그대로 둠, 더 고치지 않음): GT 파이프라인(spline + 레버암), 렌즈 = 기존 f2.22, 초점 = 수동 고정(focus 옵션은 끔), gyro rebias = 지금 기본값.
**중단**: A2b, T_cum 스윕, 새 ZUPT 패치, 75 칸 재채점, 시험마다 검토 3 명. 검토는 "앱에 넣기" 나 "보고서 결론" 직전에만 한 명이 하고, 나머지는 검산 스크립트로 충분하다.
**정리**: 패치 소스는 A2 하나와 stock 만 남긴다 (나머지는 태그만 남기고 빌드 폴더는 지운다). 벤치에서 판정에 안 쓰인 옵션(focus 5 개, still-hold)은 숨기거나 지운다.

**최소 기준 (3 개, 녹화 단위, 오프셋 3 개 중앙값)**
1. 발산 0 — GT 5 s 창 오차 > 30 cm 이면 발산
2. 이륙 3 s 최대 오차 ≤ X cm (X 는 첫 기준선으로 한 번만 정한다)
3. 기준선보다 나빠지지 않음 — ATE ≤ base × 1.2 + 0.5 cm

먼저 base 끼리 A/A 를 돌려서 통과하는 것을 확인한다.
