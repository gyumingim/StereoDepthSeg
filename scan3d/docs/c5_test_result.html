C5 시험 결과: 붕괴의 주원인이 느슨한 초기화인가

2026-10-20 · 계획 docs/c5_test_plan.md (실행 전 커밋, 변경 기록 포함) · 코드 imu_learn/c5_run.py, c5_analyse.py, vio_bench_hs.py · 결과 runs/c5/

결론: 사전 규칙으로는 C5 를 판정할 수 없다 (시험 안 됨). 사후 시험에서는 C5 가 성립하지 않는다 → 'C5 = 붕괴의 주원인' 은 철회하는 쪽이 맞다 (사후 해석).

  1. 사전 등록 설정 (a) = 앱 설정 그대로 (엄격한 정지 초기화만): 확인한 2 개 녹화 (145816, 154320) 모두 60 s 동안 한 번도 초기화되지 않았다. 녹화들은 손에 든 채 시작해서 '진짜 정지' 구간이 없기 때문이다. 초기화가 안 된 것은 반박이 아니므로 규칙대로 판정 불가.
  2. 사후 시험 (d) = 엄격한 정지 판정 + 동적 초기화 (make_ov_config --init dynamic 값): 이전에 붕괴한 녹화 7 개 중 붕괴가 사라진 것은 1 개 (132803). 기준 5 개에 크게 못 미친다 (161035 를 빼도 1/6). 이전 붕괴 녹화의 실행 기준 붕괴는 느슨 14/14 → (d) 11/14.
  3. 잘못된 '움직이는 중 정지 초기화' 는 (d) 에서 11 번 → 3 번으로 줄었지만, 그 자리를 동적 초기화 붕괴가 채웠다 (동적 붕괴 5 → 10 번). 즉 느슨한 초기화는 붕괴의 한 경로일 뿐 주원인이 아니다.
  4. 더 큰 효과는 clone 창 (사후): (d) + clone 30 (0.18 s → 0.5 s) 에서 사라진 녹화 3 개 (115620, 132803, 151358), 이전 붕괴 실행 7/14. 그래도 5 개 기준에는 못 미친다.
  5. 초기화 시간 비용: (d)·(e) 중앙 2.3 s (느슨 2.7 s), 클립의 96 % 를 덮음 → 비용 없음. (a) 는 무한대 (초기화 안 됨).

해석 (사후, 사전 규칙 밖)

  • 엄격한 0.3° 문턱도 잘못된 정지 초기화를 다 막지 못한다: 145816 시작 0 s 는 (d)·(e) 에서 0.6 s 에 정지 초기화되고 초기 자이로 바이어스 1.8 °/s → 붕괴. 152631 (거의 정지) 은 바이어스 0.4~0.7 °/s 로 정지 초기화되지만 그 뒤 카메라 갱신이 끊겨 세 설정 모두 붕괴.
  • 154320 은 이전 조사 (30 s, 시작 0/0.5 s) 에서 정상이었지만 이번에는 느슨 시작 1 s, (d)·(e) 두 실행 모두 붕괴 → 이 녹화는 초기화 순간에 민감하다.
  • 161035·163345 는 어떤 설정에서도 붕괴 (동적 초기화 뒤). 원인은 초기화 문턱이 아닌 다른 곳 (갱신 끊김·동적 초기화 품질, 확인 안 함).
  • 드론 쪽 뜻: '땅 위 정지 초기화' 를 쓰더라도 초기 바이어스 게이트 (예: ≤0.5 °/s) 와 초기화 뒤 감시가 여전히 필요하다. clone 창을 늘리는 것이 초기화 문턱보다 효과가 컸다 (손 녹화 기준, 추정).
  • 같은 실행을 낮은 부하에서 반복: 2/2 같은 결과 (145816 느슨: 비트 단위 같음, 151358 (d) 동적: 스케일 차 3e-8) → 이번 부하 (loadavg 3~14, 동시 3 개) 에서는 결정적.
