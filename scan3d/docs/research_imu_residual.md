# 정적 보정 후 남은 IMU 단독 적분 오차를 더 줄이는 방법 — 문헌 조사 + 노이즈 바닥 계산

작성 2026-10-20. 대상: Galaxy S24 IMU, ChArUco GT(240 fps, 프레임별 PnP + 롤링셔터 보정), 3 s 창에서 IMU만 적분(GT로 초기화).
현재 결과: 보정 없음 1.88 cm → 바이어스만 1.30 cm → 27-파라미터 전체 보정 0.99 cm. 작은 CNN 보정을 더해도 개선 없음.

> 결론 먼저: **0.99 cm 중 상당 부분은 IMU 쪽이 아니라 "GT 초기화 오차(초기 기울기·초기 속도)"와 "IMU-카메라 시간 오프셋"일 가능성이 크다.**
> IMU 백색잡음만으로 계산한 바닥은 3 s 끝점에서 3D RMS 약 0.5–0.7 cm(아래 §1)이고, 초기 기울기 0.01° 또는 초기 속도 2.5 mm/s 오차만 있어도 각각 0.77 cm가 생긴다.
> 그래서 가장 효과가 큰 다음 단계는 새 IMU 모델이 아니라 **B-스플라인 GT로 초기 상태를 정확하게 잡는 것 + 평가 지표에서 초기 상태 오차를 분리하는 것**이다.

## 1. 이론 노이즈 바닥 (3 s 창, GT로 초기화)

### 1.1 가정 (S24 IMU 칩은 [확인 필요])
| 항목 | 일반 폰 IMU | 고급형(예: ST LSM6DSV 데이터시트 값) |
|---|---|---|
| 가속도 잡음 밀도 N_a | 100–200 µg/√Hz | 60 µg/√Hz |
| 자이로 잡음 밀도 N_g | 0.005 °/s/√Hz | 0.0028 °/s/√Hz |
| 가속도 바이어스 불안정성 | 20–50 µg | — |
| 자이로 바이어스 불안정성 | 3–10 °/h (0.001–0.003 °/s) | — |

출처: ICM-20690(Xiaomi Mi8) 100 µg/√Hz, 0.004 °/s/√Hz — https://www.unibw.de/lrt9/lrt-9.2/preprints/2021_iss_paper_mohamedbochkati.pdf ;

### 1.2 공식 (T = 3 s, g = 9.81 m/s²)
- 가속도 백색잡음(속도 랜덤워크): σ_p(T) = N_a · √(T³/3)  (축당)
- 가속도 바이어스 상수 b_a: p = ½ b_a T²
- 자이로 백색잡음 → 기울기 랜덤워크 → 중력 새어 들어감: σ_p(T) = g · N_g · √(T⁵/20)  (수평 2축)
- 자이로 바이어스 b_g: p = g · b_g · T³/6  (수평 2축)
- 초기 기울기 오차 δθ: p = ½ g δθ T²
- 초기 속도 오차 δv: p = δv · T

### 1.3 숫자 (3 s 끝점, 계산 스크립트로 확인)
| 오차원 | 값 | 3 s 끝 위치 오차 |
|---|---|---|
| 가속도 백색잡음 | 60 / 100 / 200 µg/√Hz | 축당 0.18 / 0.29 / 0.59 cm (3D 0.31 / 0.51 / 1.02 cm) |
| 가속도 바이어스(창 안에서 상수로 남은 값) | 10 / 20 / 50 µg | 0.04 / 0.09 / 0.22 cm |
| 자이로 백색잡음 | 0.0028 / 0.005 °/s/√Hz | 수평축당 0.17 / 0.30 cm |
| 자이로 잔여 바이어스 | 0.001 / 0.002 / 0.005 / 0.01 °/s | 0.08 / 0.15 / 0.39 / 0.77 cm |
| **GT 초기 기울기 오차** | 0.005 / 0.01 / 0.02 / 0.05 ° | **0.39 / 0.77 / 1.54 / 3.85 cm** |
| **GT 초기 속도 오차** | 0.5 / 1 / 2 / 3.5 mm/s | **0.15 / 0.30 / 0.60 / 1.05 cm** |

합계(독립 가정, 3D RMS, 3 s 끝점):
- 일반 폰 IMU(100 µg/√Hz, 0.005 °/s/√Hz) + 바이어스 불안정성(20 µg, 0.002 °/s): **≈ 0.71 cm**
  (백색잡음만 0.66 cm; = √(3·0.294² + 2·0.298² + 3·0.088² + 2·0.154²))
- 고급형(60 µg/√Hz, 0.0028 °/s/√Hz) + 같은 바이어스: **≈ 0.47 cm**
- 지표가 "창 끝점"이 아니라 "창 전체 평균"이면 위 값의 약 0.4–0.5배(σ_p ∝ t^1.5 이므로 평균은 0.4배, RMS는 0.5배).
- 3D 노름의 평균은 RMS의 약 0.92배.

### 1.4 해석
- 지표가 **끝점 3D 오차**라면 IMU 잡음만으로 0.5–0.7 cm는 줄일 수 없다 → 0.99 cm 중 **약 0.3–0.5 cm만 개선 여지**.
- 지표가 **창 평균**이라면 IMU 잡음 바닥은 0.2–0.35 cm뿐 → 0.99 cm의 대부분은 IMU 잡음이 아닌 **모델/GT/시간 오차**.
- 프레임별 PnP 위치 잡음 σ≈0.5 mm, 240 fps에서 0.1 s 창으로 속도를 추정하면 σ_v ≈ 3.5 mm/s → 3 s 뒤 1.05 cm. 프레임별 PnP 자세 잡음 0.02–0.05°도 흔하다 → 1.5–3.9 cm.
  즉 **지금 GT로 초기화하는 방식 자체가 0.99 cm 대부분을 만들 수 있다** (추정 — 실제 PnP 잡음을 재봐야 함). 학습 보정(CNN)이 이득이 없던 것도 이것과 맞는다: 랜덤한 초기 상태 오차는 IMU 신호로 예측할 수 없다.
- 실측으로 바닥 확인: 폰을 책상에 두고 정지 데이터(수 시간)로 Allan 분산을 그려 N_a, N_g, 바이어스 불안정성을 얻은 뒤 위 공식에 넣는다. 정지 구간의 3 s 창 적분 오차가 곧 "모션 없는 바닥"이다.

## 2. 순위 목록 (가장 유망한 것부터)

### 1위. 연속시간 B-스플라인 GT + IMU 보정 동시 추정 (Kalibr / Rehder 확장 / Huai RS / Basalt / OpenImuCameraCalibrator)
- 방법: 카메라 자세를 B-스플라인으로 표현하고 IMU 잔차·재투영 잔차를 한 번에 최소화. Rehder 2016은 IMU 내부 파라미터(스케일, 축 정렬 오차, **g-감도**)와 가속도 축별 위치까지 추정.
  Huai 2021은 롤링셔터 카메라-IMU를 B-스플라인으로 보정, 롤링셔터 무시 시 외부 파라미터에 약 1°/2 cm 오차(시뮬레이션, 스마트폰 설정).
- 겨냥하는 오차: **GT 오차(초기 자세·속도 잡음)**, 시간 오프셋, 레버암, 롤링셔터.
- 보고된 이득: Huai — 롤링셔터 모델링으로 외부 파라미터 오차 ~1°/2 cm 제거(시뮬). Rehder — 수치는 원문 미확인.
- 폰·3 s 적용성: **높음.** 프레임별 PnP 잡음(§1.4)을 스플라인이 평균내 초기 기울기/속도 오차를 크게 줄인다. 이미 진행 중인 작업이 맞는 방향.
- 주의: 스플라인 매듭 간격이 너무 넓으면 빠른 움직임을 못 따라가 오히려 GT 오차가 생긴다(240 fps면 매듭 10–20 ms 권장, 추정).
- 출처: https://github.com/ethz-asl/kalibr/wiki/Multi-IMU-and-IMU-intrinsic-calibration ,
  https://www.research-collection.ethz.ch/handle/20.500.11850/118415 (Rehder 2016),
  https://arxiv.org/abs/2108.07200 (Huai, RS 카메라-IMU),
  https://github.com/urbste/OpenImuCameraCalibrator/ ,
  https://github.com/VladyslavUsenko/basalt , https://arxiv.org/pdf/1911.08860 (Sommer, 스플라인 미분),
  https://arxiv.org/pdf/2509.12846 (2025, 이산시간 대안, Kalibr/Basalt보다 빠름)

### 2위. 평가 지표에서 초기 상태 오차 분리 (방법론 수정, 논문 아님)
- 방법: 창마다 초기 속도 v0(필요하면 초기 기울기 2자유도)를 IMU 적분 궤적이 GT에 가장 잘 맞도록 최소제곱으로 다시 추정하고 남은 오차를 본다. 또는 Monte Carlo로 "GT 잡음만으로 생기는 오차"를 따로 계산해 빼고 보고.
- 겨냥: GT 초기화 잡음. TLIO/RoNIN 계열도 절대 위치 대신 상대 이동량(RTE) 지표를 쓰는 이유가 같다.
- 이득: 계산상 초기 속도 2–3.5 mm/s, 기울기 0.01–0.02°면 각각 0.6–1.5 cm가 지표에서 빠짐(§1.3).
- 폰·3 s 적용성: **높음, 비용 거의 0.** 1위와 함께 해야 보정 개선이 실제로 보인다.

### 3위. 시간 오프셋 정밀 추정 + 타임스탬프 정리 (IMU-카메라 동기, 지터)
- 방법: 연속시간 보정에서 시간 오프셋 td를 같이 추정(Kalibr 방식), 또는 온라인 td 추정(Li & Mourikis, RSS 2014). IMU 타임스탬프는 일정 ODR에 선형 시계 모델을 맞춰 지터 제거.
- 겨냥: 타이밍 오프셋·지터. 자이로 시간 오프셋 δt는 기울기 오차 ≈ δt·Δω 를 만든다. Δω=1 rad/s, δt=0.5 ms → 0.5 mrad(0.03°) → 3 s 동안 유지되면 최대 ~2 cm(실제로는 움직임에 따라 부호가 바뀌어 작아짐, 추정).
- 보고 수치: Android 다중 폰 동기 오차 300 µs 미만, 시계 드리프트 대부분 1.2 ms/분 미만(Skoltech 2021); 자이로 상호상관 동기로 마이크로초 수준(Twist-n-Sync 2020).
  지터는 dt 합이 망원급수로 상쇄되어 끝점 지터만 남으므로(≈ g·σ_j·√2), 오프셋보다 영향이 작다.
- 폰·3 s 적용성: **높음.** 현재 오프셋 추정 정밀도가 0.1 ms 수준인지 확인할 것. 회전이 큰 창에서 오차가 큰지 보면 바로 진단된다.
- 출처: https://roboticsproceedings.org/rss10/p57.html , https://arxiv.org/pdf/2107.00987v1 ,
  https://www.ncbi.nlm.nih.gov/pmc/articles/PMC7795013/ , https://arxiv.org/pdf/2001.00470

### 4위. 세션별(창별) 바이어스 온라인 추정 / 자기 보정 VINS
- 방법: 바이어스를 고정값이 아니라 세션마다(또는 랜덤워크 상태로) 추정. OpenVINS 온라인 자기보정(Yang 2022)은 IMU 내부 파라미터 모델·관측가능성·퇴화 움직임을 분석.
- 겨냥: 전원 켤 때마다 달라지는 바이어스(turn-on repeatability), 느린 바이어스 표류.
- 이득: 이 데이터에서 이미 확인 — 바이어스만으로 1.88→1.30 cm(31%↓). 자이로 잔여 바이어스 0.005 °/s만 남아도 0.39 cm(§1.3)이므로, 보정 세션과 평가 세션이 다르면 세션별 자이로 바이어스(정지 1–2 s 평균으로 충분)가 가장 값싼 추가 이득.
- 폰·3 s 적용성: **높음(자이로), 중간(가속도 — 정지 상태에서 기울기와 구분 안 됨).**
- 출처: https://arxiv.org/pdf/2201.09170 , https://arxiv.org/pdf/1901.07242

### 5위. 자이로 g-감도(가속도→자이로 결합) 항
- 방법: ω_m = S·M·ω + A_ω·a + b + n 의 A_ω(3×3) 추가 (Rehder/Kalibr 확장, LiDAR-IMU 보정 논문도 같은 모델).
- 겨냥: g-감도. Brossard 2020은 이 항을 일부러 무시했다.
- 이득: 폰 MEMS 자이로의 g-감도는 보통 0.01–0.1 °/s/g 범위(데이터시트 일반값, 추정). 0.01 °/s/g만 되어도 자세에 따라 0.01 °/s 바이어스와 같아 → 0.77 cm(§1.3). 다만 정적 바이어스로 이미 일부 흡수.
- 폰·3 s 적용성: **중간.** 9개 파라미터 추가, 다양한 자세로 회전한 데이터가 있으면 식별 가능. 27→36 파라미터로 늘려 보고 held-out이 줄어드는지 확인.
- 출처: https://arxiv.org/pdf/2205.03276 , https://github.com/ethz-asl/kalibr/wiki/Multi-IMU-and-IMU-intrinsic-calibration

### 6위. 온도 보정
- 방법: 축별 바이어스·스케일을 온도의 1차 함수로(TDB, TDSF).
- 겨냥: 온도 표류. LIS3DSH 6개 시험(15–55 °C): TDB 최대 약 1.3 mg/°C, TDSF 0 ~ −400 ppm/°C, 20 °C 변화에서 평균 47% 개선, 켠 직후 자체 발열 표류 43% 감소.
- 폰·3 s 적용성: **3 s 창 안에서는 낮음**(온도 변화가 거의 없음). 대신 **세션 사이**(카메라 240 fps 녹화로 폰이 뜨거워짐)에 바이어스가 달라지는 원인 → 4위(세션별 바이어스)로 대부분 해결. 폰 온도 센서 값을 기록해 두고, 보정 세션과 평가 세션 온도 차를 확인할 것.
- 출처: https://www.ncbi.nlm.nih.gov/pmc/articles/PMC9026479/ , https://zaguan.unizar.es/record/109425

### 7위. IMU 샘플 보간 / 적분 방식
- 방법: 구간 상수 대신 선형/고차 보간, 연속 사전적분(Eckenhoff 2019), 가우시안 프로세스 업샘플링(Le Gentil).
- 겨냥: 이산화 오차. 높은 샘플링(수백 Hz)에서는 작다는 것이 논문들의 공통 가정.
- 폰·3 s 적용성: **낮음–중간.** 폰 IMU가 400–500 Hz면 영향 작음. 단, 카메라 GT와 맞추는 과정(GT를 IMU 시각으로 보간)에서 생기는 오차가 더 클 수 있다 → 1위로 해결.
- 출처: https://udel.edu/~pgeneva/downloads/papers/r04.pdf , https://arxiv.org/pdf/2003.03908 , https://arxiv.org/pdf/2109.03010

### 8위. 학습 기반 IMU 잡음 제거 (Brossard 2020, Steinbrener 2022)
- Brossard 2020: 팽창 CNN이 자이로 신호를 보정(정적 3×3 보정 + 시간변화 보정), 입력 창 448 샘플(200 Hz에서 2.24 s). 자세 오차(AOE 3D): EuRoC 보정만 5.51° → 2.10°, TUM-VI 5.82° → 1.28°. 단 **자이로만**, 위치 아님, 수 분 길이 시퀀스.
  https://arxiv.org/abs/2002.10718
- Steinbrener 2022 (ICRA): LSTM/Transformer가 고속 IMU를 전처리·다운샘플해 필터 전파 오차를 줄임(LSTM이 더 좋음, 긴 전파에서도 개선). https://ieeexplore.ieee.org/document/9811989
- 겨냥: 시간변화 바이어스, 비선형성, 진동.
- 폰·3 s 적용성: **낮음.** 이득은 긴 시퀀스에서 쌓이는 자세 표류에서 나온다. 3 s 창, 정적 보정 이미 됨, 랜덤 잡음은 학습으로 못 줄임 → 이 데이터에서 CNN 이득이 없던 결과와 일치.

### 9위. 학습 관성 주행계 (TLIO, RoNIN, AI-IMU, DIDO, IMO)
- RoNIN(2019/2020): 폰 IMU로 보행자 속도 회귀, ATE 약 3.5–5.7 m(기존 17–32 m). https://ronin.cs.sfu.ca/
- TLIO(2020): 네트워크가 변위+불확실성 → EKF 갱신, 3D-RoNIN보다 모든 지표 우수. https://arxiv.org/abs/2007.01867
- AI-IMU(2019): 차량, 0 횡/수직 속도 의사측정의 공분산을 학습, KITTI 평균 1.10% 이동 오차. https://arxiv.org/abs/1904.06064
- DIDO(2022): 쿼드로터 동역학+IMU, 바이어스·보정을 함께 학습. https://arxiv.org/abs/2203.03149
- IMO(2022): TCN 변위 예측으로 EKF 갱신, Blackbird 데이터. https://arxiv.org/abs/2210.15287
- 겨냥: **움직임 사전지식**(보행 주기, 차량 비홀로노믹, 기체 동역학)으로 드리프트 억제 — 센서 오차 자체를 줄이는 것이 아님.
- 폰·3 s 적용성: **이 지표에는 맞지 않음.** "IMU 단독 적분 오차"를 줄이는 게 아니라 다른 정보를 더한다. 나중에 드론 VIO에서 비전이 끊길 때(DIDO류 동역학 사전) 쓸모 있음.

## 3. 바로 해볼 순서 (제안)
1. 정지 데이터 2–3 시간 → Allan 분산 → §1 표에 실측값 대입 → "IMU 바닥" 확정.
2. 현재 지표에서 창별 v0(+기울기)를 최소제곱 재추정한 값도 같이 보고 → GT 초기화 기여분 분리.
3. B-스플라인 GT 완성 후 시간 오프셋을 같이 추정, 회전 큰 창/작은 창으로 오차 분리.
4. 세션별 자이로 바이어스(정지 1–2 s) + g-감도 9개 추가 → held-out 비교.
5. 위가 바닥 근처까지 내려오면 학습 보정은 생략.
