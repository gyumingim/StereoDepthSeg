"가만히 있을 때" VIO 로직 — 무엇을 해 봤나

scan3d VIO 의 정지 처리 변형들을 시간 순서대로 정리. 2026-10-21 오전 ~ 10-22 새벽. 녹화 수가 적어 모든 결론은 추정입니다.

한 줄로: 이 변형들은 모두 같은 문제를 고치려는 시도입니다 — "멈춰 있는데 위치가 흐르는 것"과 "오래 멈춰 있다 출발할 때 크게 튀는 것".

① 바닥에 앉아 있는데 흐름
녹화 224323: 폰은 탁자 위에 가만히 있었는데 VIO 속도가 0.46–0.57 m/s 로 커지고, 오차가 2.7 → 48–65 cm 가 됐다. 방아쇠는 녹화를 멈추려고 화면에 들어온 손.
② 오래 앉았다 출발하면 튐
녹화 214550: 바닥에 오래 둔 뒤 움직이자 출발 뒤 10 초 오차가 44–96 cm (기준 설정). 드론 이륙과 같은 상황.

출처: docs/setdown_failure.html (결론), docs/i3_takeoff_result.md (B 결과)

먼저, 용어 (한 줄씩)

VIO — 카메라 사진과 IMU(자이로·가속도)를 합쳐 폰 위치를 계산하는 방법. 여기선 OpenVINS 프로그램.
ZUPT — "지금 멈춰 있다"고 보면 속도를 0 으로 묶어 흐름을 막는 OpenVINS 안의 기능 ("정지 갱신").
시차 (disparity) — 앞 사진과 지금 사진 사이에 특징점이 움직인 평균 거리 (픽셀). 멈춰 있으면 거의 0. 지금 문턱은 0.5 px.
초기화 — VIO 가 처음에 중력 방향·속도 등을 잡는 단계. 지금은 정지 1.0 초를 보고 함 (정적 전용).
chi² 배수 — ZUPT 가 IMU 만 보고 "정지"를 인정할 때 얼마나 너그러운지. 0 이면 IMU 로는 안 봄 (지금 설정).
헛 통과 — 실제로는 움직이는데 (정답 속도 > 2 cm/s) ZUPT 가 "정지"로 받아 준 프레임. 위험 신호.
무너짐 — 축척이 0.5–2 밖이거나 오차가 10 cm 를 넘는 실행.
ATE — 정답 궤적과 VIO 궤적을 겹쳐서 잰 평균 위치 오차 (cm).

출처: docs/setdown_mitigation_plan.md (조건 표), docs/z2_regression_plan.md (판정), docs/zupt_threshold_screen.md 1 절 (통과 조건 disp < 문턱 && features > 20)

어디에 끼워 넣었나

Z 계열 = OpenVINS 안의 ZUPT 설정을 바꿈. H · i3 = 바깥 판정기가 "정지"라고 보면 같은 사진을 계속 넣어서 시차를 0 으로 만듦 (그러면 ZUPT 가 통과). G1.0 = 같은 바깥 판정기가 사진은 안 건드리고 ZUPT 의 시차 문턱만 올림.

출처: docs/setdown_mitigation_plan.md (H 정의), docs/g10_plan.md 구현 절 (G 브리지가 프레임마다 _zupt_max_disparity 를 바꿈), docs/z2_isolate_plan.md (조건 표)

시도한 순서대로

출발점 (기준 설정, 지금 앱): ZUPT 는 영상 시차만 본다 (chi² 배수 0, 잡음 배수 10, 시차 문턱 0.5 px). 그래서 손이 화면에 들어오면 폰이 멈춰 있어도 "정지"가 아니게 되고, 그 순간 갱신할 특징점도 0 이라 IMU 만으로 적분하다 흘렀다.

Z1 — ZUPT 에 IMU 판정 켜기

버림

시차가 실패해도 IMU 가 "정지 같다"고 하면 정지로 받는다.

추가된 로직

  • 시차 검사 실패 → 대신 IMU 잔차 chi² 가 1 × (95 % 문턱) 안이고 속도 < 0.1 m/s 면 정지 갱신

바뀐 로직

H — 바깥에서 정지 보고 같은 사진 반복

버림 (다듬은 판으로 대체)

OpenVINS 는 그대로 두고, 입력 쪽에서 IMU 로 정지를 보면 정지 시작 때 사진을 계속 다시 넣는다.

추가된 로직

  • 바깥 정지 판정: 지난 1.0 초 동안 자이로 최대 < 0.05 rad/s 그리고 가속도 흔들림 (표준편차) < 0.05 m/s²
  • 정지면 정지 시작 때 프레임을 붙잡아 반복 전송 → 시차 0 → ZUPT 통과

앱에 넣으려면 필요한 것

  1. 드론 모터를 켠 IMU 기록 (프롭 없이 먼저: 시동 대기 → 공회전). 진동 때문에 정지 판정 문이 아예 안 열리면 G 는 드론에 쓸모가 없다. 가장 싸고 먼저.
  2. 천천히 미끄러지는 녹화 (회전 없이 1–5 cm/s). "회전은 없는데 움직이는" 걸 멈춘 줄 아는지 아직 한 번도 시험 안 했다 — 안전 근거의 가장 큰 구멍.
  3. 새 사전 등록: 헛 통과 정의에 "정답 표본과 앞뒤 0.1 초 이웃 모두 보드 코너 12 개 이상"을 넣고, 회귀 띠는 기준 설정만으로 재고, 분석 코드도 첫 실행 전에 커밋.
  4. 214550 같은 새 녹화 2 개 이상: 켜고 바닥에 30–60 초 → 반드시 출발. 화면 속 어둡고 무늬 없는 영역 ≤ 5 % 와 15–25 % 두 구도. 자동 노출은 잠그거나 ISO 를 기록.
  5. 모두 통과하면 G1.0 과 i3 중 하나를 고르고, 앱에는 기본 꺼짐 플래그 + 문 열림 로그만 먼저 넣는다.
