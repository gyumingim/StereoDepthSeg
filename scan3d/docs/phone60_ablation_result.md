## 결론
1. **phone60 의 손해는 intrinsics 탓이 아니다.** V1 (phone60 에서 intrinsics 만 끔) 도 발산 25 개 (phone60 23).
   → 손해는 나머지 값 (sigma_px 2 / chi2 5 / fast 20 / clones 20 / ZUPT 잡음·시차) 쪽이다. 어느 것인지는 이 시험으로 모름.
   intrinsics 만 켠 V3 는 16 → 19 로 조금 나쁘고, f 가 정상 run 에서도 중앙값 +3.7 % (최대 8.6 %) 흐른다 → **intrinsics 는 끄는 게 맞다** (f 흐름 가설은 "해롭다" 까지만 확인, 주원인은 아님).
2. **V2 (ZUPT 처음에만) = 사용자가 고른 새 기준선 `config/base_zob/`.** 기준 둘 다 통과 (발산 16 → 13, ATE 중앙값 2.53 → 2.34 cm).
   하지만 **나빠진 곳이 분명히 있다**: 131326 o0·o2 (3.4 → 2369 cm, 3.5 → 11355 cm), 154320 o1 (5.2 → 692 cm), 213341 o0 (1.4 → 9.8 cm) 이 새로 발산;
   이미 발산이던 214550 (≈20 → 47~614 cm), 224323 (≈5 → ≈250 cm) 은 더 크게 틀어짐. 좋아진 곳: 133820 전부 (≈350 → 3~5 cm), 222747 전부 (→ 2 cm), 134550 o2.
   (base_zob 템플릿 파일로 돌린 215348 o0 는 V2 와 포즈 7966 개 모두 같음 → V2 결과 = base_zob 결과.)
3. **V4 (ZUPT 완전히 끔) 가 가장 좋다: 발산 16 → 6, ATE 중앙값 2.57 → 2.00 cm, 기준 통과.** 214550·213341·133820·222747·154320·221925 (o1·o2 처음으로 초기화) 모두 정상.
   대신 **131326 3 개 모두 새로 발산 (≈3 → 250~314 cm)**, 224323 은 더 나쁨. 섞인 변수: try_zupt false 는 초기화 방식도 바꾼다 (정지 → 들어올림 대기).
   → V4 를 기준선으로 할지는 사용자 결정 사항 (지금 기준선은 V2). 131326 은 원시 IMU 가 없는 옛 녹화 (보정 IMU) 이다.
