# C5 재시험 사전 등록 (2026-10-21, 실행 전에 커밋) — 짧은 정지에서 초기화 설정이 무너짐을 바꾸나

근거: docs/overnight_verdict.md 판정 1·2·7(오늘 할 일 7). 밤샘에서는 처음 정지가 10~18 s 라 strict 와 loose 가 같은 정적 초기화를
타서 구별이 안 됐다. 드론은 이륙 전에 잠깐만 서 있을 수 있으므로, **정지를 S 초만 남기고 잘라서** 다시 비교한다.

## 질문
정지가 짧을 때(S = 1, 2, 3 s) 초기화 설정 loose / strict / strict-dyn 에 따라 "무너짐 + 초기화 안 됨" 횟수가 달라지나?

## 입력 (고정)
- 녹화 5개 (처음 정지 있음): hs_20261020_214138, 221052, 222747, 223815, 224323. 221925(정지 없음)는 이 질문에 해당 안 됨 → 제외.
- 움직임 시작 = 밤샘 정지 검출값 `runs/overnight_vio/inputs/<rec>_still.json` 의 `motion_start_s` (클립 시작 기준;
  214138 18.2, 221052 18.0, 222747 10.7, 223815 10.5, 224323 10.0 s). 이 값은 "처음으로 움직임이 들어간 0.5 s 창의 시작"이라
  실제 움직임은 이보다 0~0.5 s 늦을 수 있다 → 실제 남은 정지는 S 보다 최대 약 0.5 s 길 수 있다 (분석에서 0.1 s 창으로 다시 재서 표시).
- 자르기: 첫 VIO 프레임 = 클립 시작 + `motion_start_s − S + δ` (벤치의 기존 `--start-off` 를 그대로 씀). 남은 정지 ≈ S − δ.
- 반복: δ ∈ {−0.25, 0, +0.25} s → 3 회. (요청은 2 회였으나 저장소 CLAUDE.md 12 ② "반복 3 회 이상"을 따름.)
- **IMU 앞당김 (주)**: 0 s — IMU 도 첫 프레임 시각부터 넣는다. 벤치 기본은 첫 프레임 2 s 전부터 IMU 를 넣는데, 그러면 IMU 가 보는 정지가
  S + 2 s 가 되어 "잠깐 서 있는 드론"이 아니게 된다. 벤치에 `--imu-lead`(기본 2.0, 기존 동작 그대로)를 추가하고 이 시험만 0 을 준다.
- 설정 3 개: loose(옛 벤치 템플릿), strict(앱 정적 초기화), strict-dyn(앱 --init dynamic). 값은 `vio_bench_hs.init_values`.
- 잡음 = 앱 기본 (`--noise cfg`), IMU = Android 보정판 (유형 1/4, 밤샘 주 조건), 보정 없음, clones 11, 60 fps, 640x360, 최대 60 s, 디코드 2 스레드.
- 주 행렬: 5 녹화 × 3 S × 3 설정 × 3 δ = **135 실행**. 동시 OpenVINS ≤ 3, nice 5.
- 보조 (시간 남으면, 주 행렬 뒤): IMU 앞당김 2 s (벤치 기본), S = 1 만, 3 설정 × 3 δ × 5 녹화 = 45 실행. "IMU 가 카메라보다 먼저 돌고 있으면
  나아지나" 확인용. 주 결론에 섞지 않는다.
- 정답 = 지금 디스크의 imu_gt_spl (칸 40.70 mm 추정값). ATE 크기는 실제 칸이 44.49 mm 면 약 ×1.09 — 무너짐 판정 비율에는 거의 영향 없음
  (10 cm·축척 문턱 근처 실행만 바뀔 수 있음, 표시).
- 실행마다 결과 JSON 에 bench_blob(vio_bench_hs.py), imu_gt_blob(read_imu), make_ov_config_blob·템플릿 blob, runner_blob(c5_run.py),
  ov_bridge·libov 바이너리 sha256, 실제 yaml 원문, 초기 바이어스가 기록된다. 버전이 섞이면 판정 무효.

## 실행 단위 판정 (밤샘 c5_overnight_analyse.analyse_run 그대로)
- **초기화 안 됨**: tracking 포즈가 하나도 없음.
- **10 s 창 기준** (밤샘 사전 기준): 초기화 뒤 첫 10 s(없으면 5 s) Sim3 축척 0.5~2 이고 SE3 ATE < 10 cm → 성공, 아니면 무너짐.
- **전 구간 기준**: 초기화 뒤 전체 Sim3 축척 0.5~2 이고 전체 SE3 ATE ≤ 10 cm → 성공, 아니면 무너짐.
- 초기화됐는데 창 점수를 못 낸 실행(맞춘 포즈 < 30 / 50)은 "미판정" → **실패로 센다** (따로 표시).
- **실패 = 초기화 안 됨 + 무너짐 + 미판정**. 녹화·설정·S 마다 0~3.
- 보조 표시 (판정에 안 씀): 늦은 초기화 = 초기화 시각이 움직임 시작보다 3 s 넘게 늦음 (드론이면 이미 공중); 초기화 방식(static/dynamic);
  성공 실행의 전체 ATE 중앙값.

## 판정 규칙 (결과 보기 전 고정)
- 각 S, 각 기준(10 s 창 / 전 구간)마다 짝 비교 3 개: strict vs loose, strict-dyn vs loose, strict-dyn vs strict.
- 녹화 단위: 실패 수가 적은 쪽이 그 녹화에서 "나음", 같으면 "같음". 부호 검정(같음 제외, 양측).
- 문구: 5 녹화 모두 같은 방향(5:0)일 때만 "X 가 나음 (녹화 5개 모두, p = 0.0625, 추정)". 그 밖의 방향은 "X 쪽으로 기움 — 근거 약함".
  모두 같음이면 "차이 없음 — 근거 약함". 녹화 5개로는 어떤 결과도 "확정" 이라 쓰지 않는다.
- 드론 권고 규칙: 전 구간 기준에서, 각 설정의 "실패 0/15 인 가장 짧은 S" 를 적는다. 권고 = 그 S 가 가장 짧은 설정 (같으면 S 1~3 실패 합이
  적은 쪽, 또 같으면 앱 기본 strict). 어떤 설정도 S = 3 에서 0/15 가 아니면 "3 s 로는 부족 — 밤샘 10 s 이상에선 실패 0" 으로 쓴다.
- 미리 적는 예상 (검증 대상, 결과로 고치지 않음): strict(정적 전용, 창 1.5 s)은 S 가 창보다 짧으면 초기화를 못 하거나 늦게 할 것이고,
  loose·strict-dyn 은 동적 초기화로 넘어가 초기화는 되지만 무너짐이 늘 수 있다.
