# H 다듬기 계획 (2026-10-21, 사전 등록 — 실행 전에 커밋)

질문: H (`--still-hold 1.0:0.05:0.05`, IMU 만 보는 바깥 정지 판정이 프레임을 붙잡음) 는 내려놓기를 고쳤지만 (224323 마지막 창
24.3 → 1.26 cm) 4 묶음 (F_222747, T_214138_S2, T_222747_S1, T_224323_S1) 에서 ATE 기준을 넘었다 (docs/z2_isolate.html).
**내려놓기 고침은 지키고 3 기준을 18 묶음 모두 지키는 H 변형이 있나?**

## 실행 전에 이미 본 것 (정직하게, VIO 안 돌린 계산)
- `h_tune.py mask` = 벤치와 **같은 판정 코드**(vio_bench_hs.StillHold)로 실행마다 붙잡힐 프레임을 VIO 없이 셈. 기존 H 54 실행의
  frames_held 와 54/54 일치.
- H 가 실패한 4 묶음 (T 전부, F_222747) 은 **붙잡은 구간이 시작 정지(초기화 전·중) 하나뿐**이다. 내려놓기(224323)는 끝 구간.
  → "시작 정지는 건너뛰고, 한 번 움직인 뒤의 정지만 붙잡기" 가 첫 후보. 처음 만든 `m` (첫 비정지 프레임 뒤 켬) 은 F_214138_o0
  에서 첫 0.1 s 비정지(창 경계) 때문에 바로 켜져 시작 정지를 붙잡음 → 0.5 s 이상 계속 움직여야 켜는 `m0.5` 를 씀.
- O_154320 o2 (2.71 → 6.99) 의 H 붙잡기는 끝쪽 2 구간 (0.11 s 짧은 멈춤 + 마지막 정지) 뿐 — 시작 건너뛰기로는 안 바뀐다.
  0.11 s 짧은 멈춤은 문턱을 깐깐하게(0.03) 하거나 창을 1.5 s 로 늘리면 사라진다 (예측).

## 벤치 변경 (한 버전)
- `vio_bench_hs.py --still-hold W:G:A[:mD][:tS]`: 판정 코드를 StillHold 클래스로 옮김 (뜻 그대로) + 켜는 조건 추가.
  mD = 비정지가 D s 이어진 뒤부터 붙잡기 허용, tS = 클립 S 초부터. 옵션 없으면 예전과 같음.
- 실행기 `imu_learn/h_tune.py` (z2_isolate.py job 경로 그대로 사용 = z2_regress 인자 + --still-hold + --cfg-over).
- 모든 새 실행은 이 커밋의 blob 하나. base 는 runs/z2_regress, H 는 runs/z2_isolate 에서 읽기만 (옛 blob — 아래 det 로 같음 확인).

## 속도 (사용자: 느리다)
- 동시 5 실행 (PAR 5, 16 코어), OpenVINS `num_opencv_threads 2` (템플릿 4). 디코드 2 스레드 그대로.
- **det (먼저)**: 새 벤치 + 스레드 2 로 T_224323_S1_dm025 의 base 와 H 를 돌려, 저장된 base(z2_regress)·H(z2_isolate) 와 포즈별 최대
  위치 차가 0 인지 본다. 0 이 아니면 스레드 4 로 되돌리고 (OV_THREADS=4) 다시 det.
- **복사 규칙**: 예측 붙잡기 0 인 (짝, 변형) = base 와 입력 프레임이 글자까지 같음 → base 결과를 쓴다. 예측 구간이 H 와 같으면 → H
  결과. (결정성: DET 실행 3 개가 bit 같았음, z2_isolate.) **conf**: 복사 규칙으로 덮인 Hm05 짝 2 개 (T_224323_S1_dm025, F_222747_o1 —
  둘 다 H 실패 묶음) 를 실제로 돌려 base 와 포즈 차 0 확인. 실행한 모든 짝은 예측 붙잡기 수 = frames_held 확인.
- 긴 녹화를 창으로 자르기: **안 함** — 벤치의 중간 시작(--start-off)은 거기서 새로 초기화하는 것이라 같은 실행이 아니다.
  대신 복사 규칙이 대부분을 없앤다 (Hm05 는 54 짝 중 6 짝만 새로 돎).

## 단계
1. det (2 실행) → conf (2) + coarse (같이 큐).
2. **coarse**: 변형 4 개 × 시작 1 개 (각 실패 묶음의 최악 짝 + 224323_o0 + 223815_o0 + O_154320_o2). 복사 규칙 칸은 안 돌림.
   | 이름 | --still-hold | 뜻 |
   |---|---|---|
   | Hm05 | 1.0:0.05:0.05:m0.5 | H + 시작 정지 건너뜀 |
   | Hw15m05 | 1.5:0.05:0.05:m0.5 | + 1.5 s 정지해야 붙잡음 (짧은 멈춤 무시) |
   | Hsm05 | 1.0:0.03:0.03:m0.5 | + 문턱 깐깐 (자이로 0.03 rad/s, 가속 std 0.03) |
   | Hw2m05 | 2.0:0.05:0.05:m0.5 | + 2 s 정지해야 붙잡음 |
   (mask 에 Ht5/Ht10 (클립 5/10 s 부터), Hs/Hw2 (켜는 조건 없음) 도 계산해 둠 — Ht 는 F 녹화의 긴 시작 정지(9–18 s) 가운데서 켜져
   초기화 중에 붙잡고, Hs/Hw2 는 T 시작 정지를 그대로 붙잡아 H 실패를 되풀이할 것으로 예측 → 돌리지 않음.)
3. coarse 순위 (짝 단위): 224323_o0 에서 내려놓기 고침 (마지막 창 ≤ base 50 % 그리고 끝 정지 이동 ≤ base 50 %) 인 것 중
   짝 한도(max(base×1.1, base+0.2)) 넘은 짝 수 → 새 무너짐 → 붙잡은 동안 빠른 GT 표본 수 → 224323 마지막 창 오차.
4. **fine** = 위 1–2 위 변형을 복사 규칙 밖의 모든 짝 (3 시작, 18 묶음) 에서 돌림 → 18 묶음 전체 판정이 바로 나온다.
5. 우승 = 18 묶음 모두 통과 + 내려놓기 고침. 둘 다면 같은 순위 규칙 (실패 묶음 수 → 붙잡은 동안 빠른 표본 → 짝별 최악 → 마지막 창).

## 판정 (z2_regression_plan.md 와 같음, 묶음 = 녹화(F/O) 또는 녹화×S(T), 반복 3)
1. ATE 중앙값 ≤ max(base × 1.10, base + 0.2 cm). 2. 새 무너짐 0. 3. 헛 통과 0 (z2_regress.analyse_one 그대로).
- **수정 3' (검증자 요청, 결과 전에 추가)**: H 류는 붙잡은 프레임이 시차 0 이라 3 이 구조상 늘 0 → 진짜 시험이 아님.
  붙잡은 구간마다 GT 속도 (±0.1 s 중앙차분, z2_regress.gt_speed) 와 |gyro| 를 재서, 묶음별로
  **붙잡은 동안 GT 표본 중 > 2 cm/s 비율 ≤ 0.5 % 그리고 최대 GT 속도 ≤ 3 cm/s** 를 통과 조건에 더한다.
  (문턱은 이전 H 값 45/43660 표본, 최대 2.1 cm/s (검증자, GT 잡음 수준) 을 **본 뒤에** 정함 — 정직하게 적음.)
- 보조 (판정엔 안 씀): 짝별 (변형 − base, 같은 시작) 최악값, 짝 한도 넘은 짝. 검증자: H 의 ATE 위반 크기(0.1–0.8 cm) 는
  시작 위치 민감도 수준.
- 녹화가 적고 같은 방·같은 손 → 모든 결론은 **추정**.
