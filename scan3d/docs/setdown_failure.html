224323 내려놓기 실패 진단 (2026-10-21)

결론
  1. 폰이 놓여 가만히 있는데 VIO 가 혼자 움직였다. 224323 에서 오차가 커진 133–137 s 동안 폰은 탁자 위에 정지 상태였다 (자이로 최대 0.036 rad/s, 가속도 흔들림 0.13 m/s² 이하). 그런데 VIO 속도는 0.03 → 0.46–0.57 m/s 로 커졌고, 정답 오차는 2.7 → 48–65 cm 가 됐다 (3 실행 모두).
  2. 방아쇠 = 사람 손. 133.0–133.3 s 에 녹화를 멈추려고 손이 화면에 들어온다 (장면 변화 0.2–0.34). 바로 그 프레임부터 ZUPT(정지 갱신)가 시차 검사에서 떨어진다 (0.05 px → 1.0–1.4 px > 문턱 0.5 px). ZUPT 는 영상 시차만 보므로 (설정 zupt_chi2_multipler 0) 장면이 움직이면 IMU 가 정지라고 해도 정지로 안 친다. 확인 (시각이 프레임 단위로 맞음).
  3. 그런데 영상 갱신도 없었다. 113.8 s 의 내려놓기 충격(|a| ≈ 4.9 g) 직후 SLAM 특징이 49 → 0 개로 사라졌고(114–115 s (정정 2026-10-21, docs/initwin_setdown_verify.md: 115–116 s 에 0 — 114 s 10–20, 115 s 1–3, 116 s 0–1)), 그 뒤 정지 18 s 동안 ZUPT 가 갱신을 대신해서 새 SLAM 특징이 생기지 않았다. 폰이 정지라 MSCKF 특징도 시차가 없어 0 개. 그래서 ZUPT 가 빠지자 IMU 만으로 적분 → 속도가 초당 약 0.1 m/s 씩 커짐. 확인 (로그의 갱신 특징 수 0).
  4. 223815 도 같은 약점이 있다 — 다만 덜 드러났다. 손은 136 s 에 들어와 ZUPT 가 떨어지지만, 그때는 SLAM 특징이 9–17 개 남아 있어 VIO 가 버텼다 (오차 0.5–1.4 cm). 137 s 에 특징이 0 이 된 뒤 140–141 s 에 ZUPT 가 다시 떨어지자 속도가 0.01 → 0.04 m/s 로 오르기 시작했고, 녹화가 141.5 s 에 끝났다. 223815 의 충격은 더 약했고 (|a| ≈ 2.9 g) SLAM 특징이 17 개 남았다. 길었으면 같은 일이 났을 것 — 추정.
  5. 아닌 것: 센서 포화 아님 (가속도 최대 47 m/s² = 범위 156.9 의 30 %, 자이로 4.2 rad/s = 범위 34.9 의 12 %, 95 % 넘는 표본 0). 흐림 아님 (실패 구간에 폰 정지, 선명도 정상). 카메라가 탁자에 붙은 것 아님 (노트북 화면을 비스듬히 봄, 모서리 점 500 개 꽉 참). Android 바이어스 계단 무관 (원본 16/35 IMU). 판이 시야에서 빠진 것(117 s 부터 판 검출 0–20 %)은 정답만 끊긴 것 — VIO 는 판이 아니라 일반 특징을 씀.
대책 제안 (모두 추정, 이 녹화 2 개 근거): ① ZUPT 에 IMU 정지 판정을 같이 쓰기 — 자이로·가속도가 정지면 장면이 움직여도 정지 갱신 (zupt_chi2_multipler > 0 또는 IMU 분산 기반 ZUPT; 착륙한 드론 옆을 사람이 지나가는 경우와 같음). ② 충격 감지 → 착지 상태: |a| 가 크게 튄 뒤 IMU 가 조용하면 "착지" 로 보고 위치를 붙잡거나(ZUPT 강제), 다시 이륙 전 정적 재초기화. ③ 특징 수 게이트: 갱신에 쓰인 특징(MSCKF+SLAM)이 0 인 채로 ZUPT 도 실패하면 VIO 출력을 "믿을 수 없음" 으로 표시 (비행 중이면 호버 유지·착륙, 지상이면 이륙 금지). 이 녹화에서 ③ 은 133.0 s (오차 2.7 cm 때) 에 바로 걸렸을 것이다 — 0.5 s 안.
