   → `board_monitor_6x6.json` 의 63.403 mm 를 그대로 쓰면 정답 위치가 약 1.5 배 크다.
2. **칸 크기 추정 ≈ 41–43 mm (추정, 63.403 mm 대비 축척 0.64–0.68).**
   - 가속도계 적분 (선형 최소제곱, s·p_cam = p0 + v0 τ + g τ²/2 + ∬R f): 221925 앞 7.5 s, 1 s 창 7 개 → s = 0.656 (부트스트랩 95 % 0.54–0.68), |g| 9.785;
     2 s 창 → 0.639. 같은 방법을 모니터 녹화 hs_20261019_163345 에 돌리면 s = 1.022 (기존 scale_check 1.01–1.03 과 같음) → 방법 자체 치우침 ≈ +2 %.
     보정하면 s ≈ 0.64 → **칸 ≈ 40.7 mm**.
   - 기하: 화면에 7.0 칸이 보이고 html 은 칸 272 장치 픽셀 → 화면 폭 ≈ 1920 장치 픽셀 (1440 이 아님; 1440 은 배율 적용 후 논리 폭일 수 있음).
     보드 평면으로 편 영상(`runs/overnight_tmp/221925_rect.png`)에서 화면 밝은 영역 = 가로 7.07 칸 × 세로 4.5 칸 → 7.07×272 = 1923, 4.5×272 = 1224
     → 1920×1200 패널에 1:1 표시와 맞음. **칸 = 화면 가로 길이(mm) / 7.07** (이 관계는 배율과 무관하게 성립).
     16:10 1920×1200 패널이면 13.3"→ 40.5 mm, 14"→ 42.7 mm, 16"→ 48.9 mm. IMU 값과 맞는 것은 13.3–14".
     → 사용자에게는 "노트북 화면 가로(검은 테두리 안쪽) 길이" 하나만 재 달라고 하면 된다.
   - 불확실성: 창이 7 개뿐 (영상 앞 7.5 s 만 있음). 전체 영상이 오면 창 수백 개로 ±2 % 까지 줄일 수 있다. **자로 재기 필요** (화면의 보이는 칸 한 변).
3. 214138 (v0.2) 은 보드 종류 **미확인** (영상 업로드 중). 영상 오면 board_check.py 먼저.
