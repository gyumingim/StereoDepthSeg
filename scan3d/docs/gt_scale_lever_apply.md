# GT 축척 점검에 IMU–카메라 지렛대 적용 (2026-10-22)

근거: `docs/ate_floor_20261022.md` (ad24f0b), 검토 판정 `runs/ate_floor_review/judge.md` (3a 맞음, 3b 과장, 4 철회).

## 결론 (먼저)
- 축척 점검(`scale_ls.py`, overnight "scale check")에 지렛대를 넣었다. **OK/BOARD? 판정은 이제 `s_fixedlever` 로** 한다 (허용 폭 |s−1| ≤ 0.15 그대로). 옛 `s` (지렛대 없음) 는 그대로 찍어 예전 로그와 비교할 수 있다.
- GT 있는 녹화 23 개 (창 부족 1 개 제외) 의 s 흔들림: 표준편차 **옛 s 0.048 → s_lever 0.009 → s_fixedlever 0.007**. ate_floor 의 17 개만: 0.044 → 0.010 → 0.0068 (검토자 재계산 0.0068 과 같음).
- 23 개 모두 판정 OK. 옛 s 로는 0.87–0.89 인 녹화 (152631, 161035, 221052) 가 있었지만 지렛대를 넣으면 모두 1.01–1.03.
- 보드별 s_fixedlever 는 모두 1 보다 1.8–3 % 크다 (아래 표 2). **이 차이를 칸 크기 근거로 쓰지 않는다**: 방법(지렛대 맞춤/고정, q2) 에 따라 보드 사이 차이가 0.6–1.7 % 바뀌고, 칸을 아는 모니터 보드도 1.02–1.03 이다 → 약 1–2 % 의 설명 안 된 방법 편향 (추정). 노트북 칸은 사용자가 자·카드로 확인 (0.1570 mm/px).
- 지렛대 z 는 불확실: 녹화별로 맞추면 z 가 +0.1…−2.3 cm 로 흔들린다 (111605 +1.7). 그래서 판정은 고정값으로 하고, 맞춘 값 s_lever 는 참고로 같이 적는다.
- GT 파일은 하나도 고치지 않았다 (점검만 바뀜).
