### IMU 출처 점검 (C1·C2 가 어디서 유효한가)
- 6 면 보정은 원시 가속도 (type 35, v0..2) 로 구했다. 벤치는 새 녹화 13 개에 원시 16/35, 옛 녹화 131326·154320 에 안드로이드 보정 1/4 를 쓴다.
- **S24 는 가속도에 아무 보정도 안 한다**: 원시 IMU 가 있는 13 녹화 모두에서 type 1 − type 35 (시각 보간) 평균 0.0000, 표준편차 ≤ 0.0008 m/s²
  (대부분 정확히 0; 0 아닌 것은 보간 탓), type 35 의 v3..5 (안드로이드 바이어스 추정) 는 0. → 6 면 보정은 type 1 에도 그대로 유효.
  **C1 은 15 녹화 모두에 적용** (옛 두 녹화는 그때도 같았다는 것이 **가정** — 그 녹화엔 type 35 가 없어 직접 확인 불가). 원시 13 개만의 결과도 따로 적는다.
- C2 는 원시 자이로가 필요 (벤치가 막음; type 4 는 안드로이드가 이미 바이어스를 뺌). → **옛 두 녹화의 C2 = base 와 같은 입력** (돌리지 않고 base 값 사용),
  **C3 = C1 과 같은 입력** (C1 값 사용).
- 6 면 보정 한계: 한 번, 한 온도, 축 사이 섞임 무시 (`docs/imu_6face_20261022.md`).

### C4 변환 (카메라 좌표 r → IMU 좌표 p_CinI)
- r = 보드 GT 카메라 좌표계에서 본 IMU 위치 (p_IinC; 모델 p_imu = s·p_cam + R_bc r). VIO 카메라 = 같은 cam5 렌즈의 왜곡 편 핀홀 (x 오른쪽, y 아래, z 앞) — 같은 축이라고 **가정**.
- 벤치: `R_ci` (align.json) = IMU(기기) 축 → 카메라 축 (ω_cam = R_ci ω_imu), OpenVINS 에 T_imu_cam = [R_ci^T | p_CinI] 로 씀.
- p_CinI = −R_CtoI · p_IinC = **−R_ci^T r**. 녹화별 R_ci 로 계산: 15 녹화 모두 **p_CinI ≈ (4.58, 0.57–0.59, −1.13 ~ −1.15) cm**.
- 부호 점검: R_ci ≈ [[0,−1,0],[−1,0,0],[0,0,−1]] = `docs/s24_imu_cam_offset.md` 2 절의 이론 회전 (x_cam = −y_dev, y_cam = −x_dev, z_cam = −z_dev) 과 같음.
  거기서 카메라 → IMU 벡터 (기기 축) = (−4.60, −0.49, +1.11) cm → 카메라의 IMU 기준 위치 = (+4.6, +0.5, −1.1) cm = 위 값과 같음.
  뜻: 화면 쪽에서 볼 때 카메라는 IMU 보다 오른쪽 4.6 cm, 위 0.5 cm, 뒤(화면 반대) 1.1 cm. 후면 카메라가 뒤쪽에 있으므로 z 부호 맞음.
- z −1.1 cm 는 물리적으로 의심 (조사로는 −0.3 ~ −0.8 cm, 추정). **파일 값 그대로 씀, 조정 없음.**
- calib_cam_extrinsics 는 base 와 같이 켜 둠 → C4 는 "온라인 추정의 시작값" 만 0 → 측정값으로 바뀜.

### 점수 자 (중요: base 도 같은 자로 다시 채점)
- 예전 창 ATE (`zupt_ob_score.run_metrics`) 는 포즈의 `p` = **IMU 위치** (p_IinG) 를 카메라 GT 와 비교한다. p_CinI = 0 으로 시작해도 온라인 추정이 수 cm 로 자라므로
  base 에서도 IMU ≠ 카메라이고, C4 에서는 처음부터 4.7 cm 다르다 → C4 를 IMU 위치로 채점하면 자가 바뀐다.
- **이번 주 지표 = 같은 함수를 카메라 위치 (T_world_cam0 의 이동) 로 계산한 창 ATE 와 발산 판정** (창 ATE > 50 cm 또는 rel5 > 30 cm), base 와 모든 변형에 똑같이.
  옛 IMU 위치 지표 (ate_w_imu) 도 같이 적는다 (보고만).
- Sim3 축척 = 벤치 `scale` (카메라 포즈, Umeyama Sim3). 칸마다 base·변형 모두 보고.
